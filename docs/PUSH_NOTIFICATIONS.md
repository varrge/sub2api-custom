# 推送通知

入口：**系统设置 → 推送通知**。每个渠道可以单独配置接收地址、触发事件、标题、Markdown 正文和标签，最多 10 个渠道。

## 配置

- **Server 酱**：填写 SendKey，支持 `SCT…`（Turbo）和 `sctp…`（Server 酱³）。通道编号可选，多个编号用 `|` 分隔。
- **自定义 Webhook**：填写公网 HTTP/HTTPS 地址，选择 JSON 或表单格式。链接中的令牌会按凭据保存；禁止内网地址和重定向。
- 保存后密钥／链接不再回显，留空表示保留。不同渠道可以接收不同的事件。
- 标题、正文、标签支持下表变量。正文支持 Markdown；标签以 `|` 分隔。Server 酱³ 使用原生标签，Turbo 将标签附在正文中。
- 先生成预览，再保存。**真实测试发送**会向已保存的渠道发送测试通知，总开关关闭时也允许测试；每个渠道 30 秒内最多一次。
- 打开总开关和渠道开关后，只接收启用后发生的新事件，不补发历史订单。

## 事件

| 事件 | 触发条件 |
| --- | --- |
| 充值成功 | 在线余额充值订单完成到账 |
| 订阅购买成功 | 订阅订单完成履约 |
| 月卡购买成功 | 月卡已发卡且订单完成；未发卡的自动退款订单不通知 |
| 拼团已满 | 拼团首次达到满团；同一团不会因状态来回变化而重复通知 |
| 运行告警 | 已配置的运行监控规则生成告警记录 |
| 共享额度不足 | 共享活动生效期间，可用原价额度（总额减已用、预占）低于或等于渠道阈值；每个活动配置版本提醒一次 |
| 管理员操作 | 敏感管理员接口：账号/代理/兑换码导出、备份创建与恢复、S3 配置、审计清空、管理员 Key 读写、用户增删改、推送设置；以及找回密码、重置密码请求（含失败尝试）。10 分钟内最多入队 60 条 |
| 管理员账号登录失败 | 已识别目标为现存管理员的密码、二次验证、通行密钥及 OAuth 绑定登录 4xx 拒绝；普通用户、不存在的账号、成功登录和 5xx 服务故障不触发 |
| 异常 IP／未授权访问 | 未匹配路由的敏感路径探测（如 `/.env`、`/.git/`）；同一 IP 一分钟内 3 次未知 API 的 404/405，或 5 次管理接口未认证拒绝、模型接口无效凭据/IP 限制拒绝 |
| IP 已永久封禁 | 自动规则或管理员新增永久封禁时通知（见下文「IP 永久封禁」）；每 10 分钟最多 60 条，迁移回填的历史封禁不通知 |

管理员操作推送以审计记录为准，附带操作名、账号、来源 IP、认证方式、接口、状态码和请求 ID。`auth_method=admin_api_key` 表示调用方使用的是管理员 API Key，而不是网页登录会话。

这里的额度不足指全站共享额度；不逐次检查每个用户余额。管理员手工改余额、兑换码充值不属于在线充值事件。

## 安全通知与 IP 记录

升级到包含迁移 `273_admin_login_failure_push_scope.sql` 的版本后，在渠道的事件列表中勾选「管理员账号登录失败」和／或「异常 IP／未授权访问」，保存并开启总开关及渠道开关。事件键仍为 `security.login_failed`，原有订阅保留并自动收窄范围。迁移取消旧范围的待发送通知及重试、移除旧事件队列，保留审计和已发送历史；已经发出的请求无法撤回。未订阅的渠道不会自动开启。

- 安全通知使用 `server.trusted_proxies` 解析客户端 IP，同时保留直接连接应用的对端 IP 和解析来源。即使开启兼容模式，也不会直接采用任意请求携带的转发头。必须正确配置受信代理，并由反代清理、重写来自不可信客户端的转发头；VPN/代理出口地址不等于使用者身份。
- 密码／OAuth 绑定登录先用服务端查到的用户 ID 识别目标；验证码或限流提前拒绝时，仅把提交的邮箱用作查询线索，须与数据库唯一匹配且角色确实为管理员。通知单列「目标管理员账号」，不把它写成已认证操作者。请求自报的角色或用户 ID 不参与判断。
- 二次验证通过服务端临时会话识别目标，通行密钥通过已存储的凭据识别目标；在识别账号之前就失败的请求（例如失效且已删除的临时会话、无法解析的通行密钥请求、无用户名的通行密钥开始请求）不会触发管理员登录通知。普通用户的失败不会占用这类通知的限频额度。
- 通知不包含请求体、Cookie、Authorization、Key 片段或任意未知路径中的参数。
- 所有模型接口兼容路径通过鉴权拒绝原因识别。余额不足、欠费、Key 过期/额度耗尽、分组限制及上游 401/403 不当作异常 IP；无效凭据触发的 429 限流属于安全事件。
- 登录失败沿用认证审计；探测和重复未授权请求在「审计日志」中分别记录为 `security.ip_probe`、`security.access_denied`，可按客户端 IP 查询，详情含 `peer_ip`、`ip_source`、`reason`、`request_count`。`request_count` 是触发时的计数，不是整段时间的总请求数。
- 探测/未授权汇总每个进程按 IP、动作每分钟最多记一条，内存最多保留 4096 个窗口。达到容量时新来源暂不汇总，原始访问日志仍可用于核查。登录失败审计不受此汇总限制。
- 两类安全通知共用每 10 分钟固定窗口最多 60 个事件的全局入队上限，同一 IP、同类事件每窗口最多入队一次；一个事件可投递多个渠道。审计延迟写入也按实际入队窗口限频，并保留发生时间，避免重新开启渠道时补发旧事件。限频不会删除审计记录；通知传输失败后的重试仍可能造成接收方重复收到。
- 该检测位于应用内。CDN、WAF、防火墙或反代已经拦截、未到达应用的请求，需要在对应入口日志中查看，不会生成此处的通知。

## IP 永久封禁

迁移 `274_ip_bans.sql` 新增应用内永久封禁。被封禁的客户端访问网页、管理后台和模型接口都会直接收到 403（`IP_BLOCKED`）；`/health` 与支付回调不受影响。封禁不会自动过期，只能在后台「IP 封禁」页面解除。

**前置条件：** 必须设置 `SERVER_TRUSTED_PROXIES`（或 `server.trusted_proxies`），值为反向代理连到应用的地址（Docker 部署中通常是 Caddy/Nginx 容器的固定 IP）。封禁判断只信任受信代理链，不采用兼容模式下的原始转发头。未配置时应用看到的所有请求都来自代理，而内网地址永远不会被封禁，所以自动封禁实际不生效，后台页面也会给出提示。

自动规则（后台「封禁规则」可调整）：

| 规则 | 默认 | 说明 |
|---|---|---|
| 诱饵账号 | `admin@sub2api.local`、`root@sub2api.local`、`admin@sub2api.org`、`admin@sub2api.com`、`admin@example.com`、`admin@test.com`、`admin@admin.com` | 登录、注册、找回/重置密码、发送验证码、通行密钥开始及 OAuth 绑定登录中使用这些邮箱，立即永久封禁，本次请求返回与密码错误相同的 401，不进入限流、验证码或发信。邮箱若属于真实账号则自动忽略，后台会提示移除 |
| 敏感路径探测 | 开启 | `/.env*`、`/.git/*`、`wp-login.php`、`/wp-admin/*`、`phpinfo.php` 一次即封 |
| 管理员账号登录失败 | 15 分钟 5 次 | 仅统计目标为现存管理员的失败；普通用户失败不计 |
| 无凭据访问管理接口 | 10 分钟 10 次 | 携带 JWT 的过期会话不计 |

保护规则：内网、回环、链路本地、CGNAT 地址，配置的受信代理，后台白名单，以及近 30 天内成功完成过管理员请求的地址，都不会被自动封禁；手动封禁也不能覆盖内网、受信代理和白名单。IPv6 自动封禁按 /64 网段。关闭「启用自动封禁」只停止新增自动封禁，已有封禁继续生效。

迁移会把历史审计中尝试过 `*@sub2api.local` 的公网来源回填为封禁（来源标记为「历史回填」，不推送）；同一地址若有任何正常账号成功使用过，则留给管理员人工判断，不自动回填。

封禁名单保存在 PostgreSQL，各实例每 10 秒同步一次。后台不可用时可直接执行：

```sql
UPDATE ip_bans SET revoked_at=NOW(), revoked_by='sql', revoke_note='emergency'
 WHERE ip='<IP 或网段>' AND revoked_at IS NULL;
```

## 模板变量

| 变量 | 含义 |
| --- | --- |
| `{{site_name}}` | 站点名称 |
| `{{event_name}}` | 事件中文名称 |
| `{{event_id}}` | 事件编号 |
| `{{occurred_at}}` | 北京时间 |
| `{{summary}}` | 事件摘要 |
| `{{details}}` | 预置的 Markdown 事件详情 |
| `{{user_id}}` / `{{order_id}}` / `{{amount}}` | 订单用户、订单编号、实际支付金额 |
| `{{currency}}` | 支付币种，例如 CNY、USD |
| `{{product_name}}` / `{{team_code}}` | 月卡名称、团号 |
| `{{remaining_quota}}` | 共享剩余额度（USD） |
| `{{action}}` / `{{method}}` / `{{path}}` | 管理员操作名、HTTP 方法、接口路径 |
| `{{client_ip}}` / `{{actor_email}}` / `{{auth_method}}` | 来源 IP、操作账号、认证方式 |
| `{{target_user_id}}` / `{{target_email}}` | 管理员登录失败的目标账号 ID、邮箱；不代表账号本人操作或成功登录。IP 封禁事件中 `target_email` 为被尝试的诱饵账号 |
| `{{ban_id}}` | IP 封禁记录编号 |
| `{{status_code}}` / `{{request_id}}` | 响应状态码、请求 ID |
| `{{peer_ip}}` / `{{ip_source}}` | 安全事件的连接对端 IP、解析来源（`direct_peer` / `trusted_proxy_chain`） |
| `{{reason}}` / `{{request_count}}` | 安全事件触发原因、触发时请求次数 |

当前事件没有的字段会替换为空，建议用 `{{event_name}}` 作为标题，用 `{{details}}` 展示对应事件的具体信息。Server 酱标题最多保留 32 个字符。

```markdown
## {{event_name}}

{{summary}}

{{details}}

---
站点：{{site_name}}
时间：{{occurred_at}}
```

## 自定义 Webhook 请求

使用 HTTP POST；JSON 和表单字段一致：

```json
{
  "title": "拼团已满 · 示例站点",
  "desp": "## 拼团已满\n\n- **团号**：T-demo",
  "tags": "月卡|运营",
  "event": "team.full",
  "event_id": "42",
  "occurred_at": "2026-11-04T08:00:00Z"
}
```

返回 HTTP 2xx 视为成功；Server 酱还会检查响应中的成功状态码。自定义渠道是通用接口，第三方服务若要求不同的 JSON 结构，需要使用自己的转发地址适配。

## 投递记录与重试

通知在独立队列中发送，约每 15 秒处理一次，不等待第三方 HTTP 返回来完成订单。发送失败最多尝试 3 次，前两次失败后分别等待至少 30、60 秒；服务重启后继续处理待发送记录。后台显示最近 50 条结果、次数和失败原因。

每个渠道的同一业务事件只入队一次。网络超时可能发生“接收方已收到但发送方未收到响应”，因此重试仍可能产生重复通知；自定义接收方可按稳定的 `X-Notification-ID` 请求头去重。

关闭渠道、取消事件、修改地址或关闭总开关会取消相应待发送通知及失败重试。已经发出的请求可能完成，无法撤回。模板变更影响之后入队的通知。
