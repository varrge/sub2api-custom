# 企业注册邀请

企业用户在左侧「注册邀请」中申请一次性邀请码、复制注册链接、查看使用记录。邀请的新用户仍走普通注册流程，不自动成为企业用户。

## 申请规则

- 复用现有注册邀请开关、等级、申请数量限制与有效期。
- 等级按累计有效充值计算，管理员可以在「注册邀请管理 → 用户等级」中查找企业账户并指定等级。
- 企业用户页面仅显示邀请额度，不展示邀请等级、充值升级进度或等级列表；后台额度规则和管理员等级设置保持不变。
- 申请沿用 UUID 幂等键；重复确认同一次申请不会多占额度。
- 用户只能查看自己的邀请码，被邀请人的邮箱继续脱敏。

## 无返利规则

- 企业用户不显示返利比例、返利汇总、首充返利页签或自动入账提示。
- 企业签发的邀请码保存 `rebate_eligible=false`，即使以后转回个人账户，也不会补发返利。
- 个人时期签发的码，如果使用时邀请人已是企业账户，也不参与返利。
- 首次有效充值时任一方为企业账户，该邀请永久失去返利资格，后续充值不能代替首充。
- 注册归属仍保留，因此不会绕到旧版邀请返利通道。
- 企业用户不能调用自己的返利列表接口。管理员仍可审计历史个人返利；已合法赚取的历史记录不会被本次功能删除。
- 普通个人用户原有申请和返利流程保持原规则。

## 数据库与验证

新增迁移 `277_enterprise_registration_invitations.sql`，给 `native_invitations` 添加返利资格字段。已有记录默认保留资格；新企业码显式关闭资格。迁移重复执行不会重置已有标记。

验证覆盖企业菜单和路由、申请与复制、额度和开关、管理员指定等级、一次性注册、充值、旧返利抑制、OAuth 失败回滚、账号转换以及并发转换。数据库测试使用本地独立 PostgreSQL；不读取或写入生产数据。

发布应随项目版本通过 GitHub Actions 构建，包含该迁移和前后端变更。
