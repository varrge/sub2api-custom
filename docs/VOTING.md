# 投票

管理员在“系统设置 → 功能开关 → 投票入口”打开开关（默认关闭）。右上角投票入口位于消费榜左侧，消费榜隐藏时不留占位。关闭开关后用户列表、详情、提交接口均停止访问；管理员仍可使用“投票管理”。

点击右上角“投票”直接向下展开小弹窗，不跳转独立页面。在弹窗内切换投票、多选、二次确认提交和查看结果；点击外部或按 Escape 关闭。仅展开时加载数据，手机端按视口收窄并在内容区滚动。后台保留独立的“投票管理”页面。

“投票管理”支持创建、编辑、查看结果和删除未有人参与的投票。状态包括草稿、进行中和已结束，草稿不向用户展示。已发布的投票不能退回草稿。可以设置标题、说明、封面，以及 2–12 个带可选图片的选项。支持 PNG、JPEG、GIF、WebP，单图最多 300 KiB，最多 4000 万像素；图片保存在投票记录内，不依赖第三方图床。

登录且有效的用户（包括企业用户）可以选择一项或多项并提交。提交前要求确认，提交后不可撤回或修改。每个选项的票数为选择该项的用户数，参与人数按用户去重，多选时各项百分比之和可能超过 100%。投票结果不包含参与者身份；操作审计保留用户参与某项投票的记录，但不记录其选项内容。

有参与者后锁定选项文本、配图和顺序，保留标题、说明、封面和状态编辑。服务器使用版本号拒绝过期的编辑或投票请求，数据库唯一键与事务锁防止并发重复投票及编辑/关闭竞态。有票投票只能结束，不能删除。

数据库迁移 `264_voting.sql` 新建投票和选票表，并初始化关闭的开关。部署按现有迁移流程自动执行，无需手工创建表。

用户 API：`GET /api/v1/voting/polls`、`GET /api/v1/voting/polls/:id`、`POST /api/v1/voting/polls/:id/votes`。管理员 API 使用 `/api/v1/admin/voting/polls` 前缀，提供列表、详情、创建、更新、删除。列表支持 `page` 和 `page_size`，不返回图片内容；详情按需加载。

真实 PostgreSQL 测试使用 `VOTING_TEST_DSN`（URL 格式）。测试会创建并清理独立 schema，不接触应用数据：

```sh
VOTING_TEST_DSN='postgres://localhost/postgres?sslmode=disable' go test -race ./internal/voting
```
