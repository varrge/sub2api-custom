## 发布和回退边界

执行 Downloads 中《Sub2API-自定义版本更新与灾备手册》的既有流程。用户追加授权中国部署和隧道访问后，已构建当前工作区候选镜像并部署独立隔离验收实例。GitHub CI、正式版本和生产切换尚未执行；该实例不代表正式发布验收完成。

- 数据库增加有序 `group_ids`、不可逆权限模式 `multi_group_enabled`，保留 `group_id` 为首组兼容投影；任务保留创建分组；迁移 237 增加批次权益快照。
- 旧程序可以读取迁移后的首组字段，但不能理解多组权限边界、会话归属及新任务快照，不能把“数据库可读”当成“行为完全兼容”。启用多组选项后，回退前应暂停调用和异步任务处理，核对旧版本的兜底行为与未结算任务，使用经验证兼容的版本或向前修复。
- 存在新版本创建且尚未结算的订阅批次时，不能直接降级到不识别 `billing_snapshot` 的旧程序，否则旧程序的余额冻结结算路径无法处理它们。应先完成或由兼容版本处理这些任务。
- 旧视频任务在升级前没有保存的价格，无法从当前数据库恢复为历史价；保留原有降级路径。新任务保存创建时价格。
- 发布前需在隔离 staging 验证数据库迁移、真实模型调用、跨组实际账单、月卡独立额度、密钥合计限额、长连接撤权、历史任务以及固定镜像回退。不能用单元测试代替真实上游验收。
- 此轮使用中国 staging 的独立数据库副本，未覆盖原 staging，也未操作日本生产。

## 异步批量任务补充验证

- 月卡和旧订阅批次创建时持久化原分组、候选权益、窗口和代次；订阅组不错误冻结余额。
- 原密钥/账号软删除、密钥改绑、订阅到期、窗口重置后，已接受任务仍按原快照结算。
- 余额实际扣款与密钥总消费及时间窗口计数在同一事务中完成，重复请求不重复扣款。
- 月卡延迟恢复与批次状态重试保持可协调；超过旧重试次数后也不会出现后台扣款却任务提前失败的状态。
- 没有余额冻结的订阅任务在上传阶段进程中断后能进入过期未提交任务恢复。
- 普通单分组密钥的批次提交也检查时间窗口及 RPM；候选组探测不重复计次。

## 建议 staging 验收路径

1. 将已有单组密钥改为多个有序分组，客户端继续使用原密钥；核对密钥字符串、额度和到期时间未变。
2. 配置不同平台/模型的组，确认每次调用实际组；第一组额度耗尽时转入已选的可用组，未授权组不可配置或使用。
3. 交替调用不同组，核对密钥总额度及 5h/1d/7d 窗口累计；核对各组订阅/月卡分别结算。
4. 更新排序、停用/撤销原组权限后继续 Responses/WS/Realtime/Live，确认不默默转组，撤权明确终止。
5. 图片/视频/批次创建后修改价格、解绑原组、耗尽密钥额度，核对结果仍可查询、费用遵守创建快照；停用密钥/用户后查询应被拒绝。
6. 检查普通用户多选、管理员代配置、按次选组筛选、批量换组、目录别名及 Codex 模型元数据。
