## 已确认的需求

- 拼团大厅展示正在招募的订阅分组月卡团；月卡单购和开团位于现有“充值/订阅”的“拼团”页签，已购月卡并入现有“我的订阅”。
- 同一用户可购买并持有多张相同订阅分组的月卡，但已经参加某一团后不能再次参加该团，只能参加其他团。
- 一个拼团有一个共享团号，每张已购月卡另有独立卡号；用户通过团号或分享链接查询并加入拼团。
- 所有登录用户均可开团，发起人付款成功后正式开团。招募期默认 48 小时，由管理员按商品配置；已付款人数达到该团人数上限时满团并提前结束招募。
- 月卡通过在线支付购买，从支付成功时刻开始计时，30 天后过期；不等待前一张卡消耗完成才开始计时。
- 第一张月卡总额度或本周额度用完后自动切换后续可用卡，用户可以手动调整消耗顺序。每次新调用按排序寻找第一张可用权益；前面的卡周额度恢复后重新优先使用。
- 一次调用允许按消耗顺序跨卡分摊；卡额度不足覆盖实际调用费用的部分，按正常调用计费从账户余额扣除。例如仅一张卡剩余 1、实际调用费 3，则卡扣 1、余额补扣 2；多张卡依次分摊后仍有差额时适用同一规则。正常调用计费沿用现有实际费用口径，补扣仅针对差额，不重复扣整笔。
- 新请求必须有至少一份属于该分组、有效且有可用额度的订阅权益；全部卡周额度耗尽、总额度耗尽、过期或没有卡时停止新调用。余额仅补扣已开始调用的差额，不支持凭余额绕过该订阅分组的权益准入。
- 已发生调用的差额可将账户余额扣成负数；负余额时阻止该账户后续调用，即使其他卡仍有额度也先结清欠费。充值结清后恢复正常准入；已在途的并发请求继续结算，可能扩大负余额。卡购买和周额度重置不抵销欠费，登录、查看账单和充值等处理欠费的功能保持可用。
- 调用开始时确定候选订阅权益、消耗顺序以及各卡所属周周期，完成后按实际费用分摊。调用跨过周重置或卡到期时，仍计入开始时的周期及当时有效的卡，不挪用下一周额度；中途调整排序或购买新卡只影响后续调用。并发结算合计不能重复消耗同一份卡额度，剩余费用补扣余额。
- 周限额为月总额度 / 4，每张卡从支付成功时刻起每 7×24 小时重置。例如周三 15:00 付款，下周三 15:00 首次重置。周额度不累加到下一周，月累计消耗始终保留。
- 第 29 天进入有效期内的第五个周额度周期，仅覆盖最后两天。可用额度是该卡周剩余额度与整卡剩余额度中的较小值；有效期满 30 天后不再用于新调用，已开始调用仍按其归属周期结算，结算后未用权益失效。
- 示例每张卡售价人民币 198 元，940～1100 为每张卡独立享有的美元调用额度，沿用系统现有调用费用计费口径。
- 付款成功即可使用基础额度 940；同团人数达到 3、6、10 时，全团已购卡额度依次升至 960、1000、1100。升级同时提高周限额，保留已用量、周重置时间和到期时间。例如本周已用 235 后升至六人档，当前周新增 15 可用额度。
- 拼团上线后旧订阅逐步淘汰，但已拥有的旧订阅保留原额度、期限、重置规则，并与同分组新卡一起参与可调整的消耗顺序；已确认的账户欠费准入仍适用。旧订阅经内嵌入口销售，其停售、续费入口及过渡由用户自行处理，本功能不自动关闭或改造旧销售流程。
- 沿用原分组 API Key，同一用户同一分组下的全部 API Key 共享订阅权益、用量和消耗顺序。
- 每个商品绑定一个订阅分组；管理员可配置售价、基础额度、人数档位及各档额度、满团人数、招募期；有效期固定 30 天，周限额固定为该卡总额度 / 4。开团时固定团规则，商品修改仅影响新开的团，老团后来加入者仍按老团规则购买，已有卡权益不被商品配置改写。
- 月卡购买沿用旧订阅的销售权限语义：启用且未删除的用户可购买在售月卡或参加可加入的团，对应分组必须启用、未删除且为订阅类型。专属分组标记、用户的公开分组限制和标准分组白名单不作为购卡前置条件；支付成功后凭有效月卡取得订阅分组的使用权，不写入永久白名单。履约时再次核对用户和分组状态。
- 招募结束未满团仍保留已达档位，截止后停止加入且不自动退款。例如四人各得 960、八人各得 1000。
- 付款后不支持自助退团，退款由管理员审核；退款成功撤销对应月卡，其他成员已获得的额度不回收。退款用户不贡献后续升档人数，已结束的团不重新开放。同一用户仍不得重复参加同一团。
- 若支付到账时因超时或名额已满而无法入团，原路退款。实现通过订单/团锁及唯一约束裁决名额与截止竞态，未成功发卡的已付订单保存为持久退款任务。

| 示例档位 | 月总额度 | 按公式计算的周限额 |
| --- | ---: | ---: |
| 单独购买或 1～2 人 | 940 | 235 |
| 3～5 人 | 960 | 240 |
| 6～9 人 | 1000 | 250 |
| 10 人满团 | 1100 | 275 |

人数按不同的已付款用户计，同一用户不能重复参加同一团。中间人数取最近已达档位，达档立即升级并保留已用量。单独购买保留独立入口，生成使用商品基础额度的独购月卡，不参与团购升档；其他月卡计时、周限额及结算规则相同。

## 首版页面与运营范围

- **拼团大厅**：按图 1 展示正在招募的月卡团，包含商品名、团号、倒计时、人数进度、当前额度、相对基础额度的提升、下一档额度及参团按钮；提供刷新、按分组筛选和团号查询。团结束后从招募列表移出，历史详情可通过团号及我的订阅访问。
- **我的订阅**：直接扩展现有页面，按图 2 将每张月卡单独展示，和已有旧订阅共存，提供统一的“调整消耗顺序”。展示卡号、所属团、获得和到期时间、周额度和总额度已用及剩余量、周期及重置时间。逐次调用扣费明细包含各卡分摊及余额补扣；账户欠费提供充值提示。
- **充值/订阅 → 拼团页签**：按图 3 将原“订阅”页签改为“拼团”，保留充值功能，在此展示在售月卡商品与“单独购买”“发起拼团”操作，并链接到拼团大厅参加已有团。页面整体标题与导航文案同步为“充值/拼团”属于展示建议，最终以现有导航结构实现为准。
- **独购**：在上述页签单独购买商品基础额度月卡（示例 940），拥有独立卡号；该卡不加入拼团，也不参与后来升档。用户可以另购月卡开团或加入其他团。
- **管理后台**：沿用前轮方案配置商品、价格、人数档位、额度、招募期，提供团/成员、订单、卡及扣费记录查询，支持人工退款及操作记录；退款采用已确认的 Q14 规则。
- **旧订阅过渡边界**：用户自行处理旧内嵌销售入口和停售安排。系统继续展示并兑现已有订阅权益，不自动禁用旧订阅 API、续费、兑换码或已有订单履约。

实现建议：初始消耗顺序按最早到期优先、同到期按购买时间；新卡追加末尾，保留手动排序。商品下架停止新独购和新开团，已开始的团和已售卡按既有规则继续；该后台操作应清楚显示影响范围。
