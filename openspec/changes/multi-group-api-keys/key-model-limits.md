# 密钥模型限制

编辑密钥时，表单最底部新增「模型限制」。默认关闭，旧密钥不受影响；开启后只允许调用勾选的模型，至少选择一个。管理员在用户密钥编辑窗口也可代为配置。

## 使用行为

- 候选列表合并当前所选单个或多个分组的模型，同名模型只显示一次，支持搜索、全选和清空。
- 目录接口按密钥所属用户的分组资格校验；管理员查询同样遵守该用户已有资格。包含账号映射、分组模型白名单、合成分组公开别名、Gemini 混合账号及固定 OpenAI 模型发现配置。通配符账号映射会结合分组具体名单及平台目录展开为可勾选名称。
- 修改分组或目录加载失败时，不会自动清空已保存的限制。已选但当前目录中没有的模型单独标记，可手动取消；这样不会因暂时目录故障把限制变成无限制。
- 模型名称以客户端使用的公开名称精确校验，区分大小写；推理后缀和别名需要分别勾选，仅在 Gemini 目录边界去除 `models/` 资源前缀；普通公开 ID 不自动去除前缀。后台只接受具体模型 ID，不接受通配符。
- 密钥限制与分组规则共同生效，勾选模型不会授予新的分组权限或订阅资格，不改变整把密钥共享的消费和限流计数。
- 客户端模型目录也按密钥限制过滤，包括普通 `/models`、Codex manifest、Gemini 目录及批量生图目录；过滤后为空仍返回空目录。

## 实现边界

`api_keys.model_allowlist` 保存 `{enabled, models}`，迁移 `244_api_key_model_allowlist.sql` 为历史行和旧客户端创建的密钥提供关闭限制的默认值。更新请求省略该字段则保留原配置；用户及管理员写入使用字段级更新，模型限制编辑不覆盖累计用量。鉴权缓存快照升级到 v27，编辑后失效缓存。

鉴权在校验密钥、用户与 IP 后、分组选择及模型映射前检查模型限制。HTTP 检查 JSON 重复/大小写变体、multipart、Gemini URL、Live session.model 及 Realtime 模型。Responses WebSocket 首帧和后续 turn 都检查，首帧重读最新密钥限制；图片和 Live 接口还检查缺省生效模型；Live 保存映射前公开模型，Live／Realtime 对后续计费帧与 `session.update` 重验最新限制。Live 通话创建后固定模型，切换模型需要新建通话，避免重连丢失会话模型状态；有歧义的 Live 重复模型字段直接拒绝。已归属用户的历史资源读取仍按原有所有权规则进行。

目录过滤保留提供方元数据，密钥过滤后的响应使用独立 ETag，防止旧目录缓存绕过新的可见范围。管理页面目录来自用户 JWT/管理员鉴权，不暴露或借用密钥值。

接口：

- `POST /api/v1/keys/model-options`
- `POST /api/v1/admin/users/:id/key-model-options`
- 请求：`{"group_ids":[3,25]}`；结果：`{"models":[{"id":"model-name","group_ids":[3]}]}`（沿用面板响应包裹）。
- 用户编辑与管理员编辑均接受可选的 `model_allowlist` 对象。

## 验证与发布

前端：50 项定向测试、类型检查、变更文件 ESLint、生产构建通过。后端：真实 PostgreSQL/Redis 集成测试验证迁移、持久化、鉴权投影、旧值保留与并发计费不被覆盖；HTTP/WebSocket/默认图片模型和目录过滤有回归测试。中间件、路由、handler、service、repository 与迁移整组测试通过，随后 Live 固定模型与歧义字段回归通过；独立审查发现的别名匹配、通配符目录、批量生图分组过滤与长连接问题已修正。golangci-lint 通过。

本功能与前一提交的模型日志、Codex 预检修复一起保留在 `feature/api-key-model-limits` 分支。本次未发布 tag 或修改中国/日本部署；日本生产切换继续遵循灾备手册的单独确认流程。
