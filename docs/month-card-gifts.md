# 批量赠送额度卡

入口：后台「月卡拼团」→「赠送额度卡」。默认名称为「狂蹬卡」。管理员设置适用订阅分组、每人总额度（USD）、有效天数（1–365），预览人数与总赠送额度后确认发放。

## 领取资格

- 发放时持有至少一张已生效、未过期、未删除或撤销的付费月卡；订单状态为 `COMPLETED` 或 `REFUND_FAILED`。
- 按账号去重，每个批次每账号一张。拥有多张月卡也只发一张；不同批次可再次赠送。
- 额度已耗尽但月卡未过期仍符合资格。默认包含冻结月卡，按暂停计时计算有效期；管理员可取消包含冻结卡。
- 可筛选已有月卡所属分组。适用号池与筛选分组分别设置。
- 禁用、删除和企业账号不参与。赠卡自身不作为后续赠送活动的资格来源。

## 使用规则

赠卡独立出现在「我的拼团」卡包，发放后立即生效。只有一次性总额度，不按周恢复，不可冻结。过期后不再参与扣费，也不显示在有效卡包中。它默认排在同组现有权益后，用户可以拖动调整消耗顺序。

不会增加余额、生成付款订单、占拼团人数，或触发月卡购买促销和企业余额折算。正在进行的调用仍遵循现有月卡结算规则，包括超出额度的余额补扣。

管理员可在单购卡权益列表查看赠卡、调整总额度和重置累计用量。含赠卡的批量编辑只支持总额度/累计用量。重置会保留历史账务及重置前已开始调用的结算归属。

## 发放与重试

预览绑定配置及符合资格的账号集合。确认时重新核对，名单变化返回 409，需重新预览。每个批次在同一数据库事务中完成，失败全部回滚。

请求 ID 唯一；重试同一请求返回原批次，不重复发卡。页面把尚未确认的请求保存在当前浏览器标签页的会话存储，刷新或断线后可以继续查询/重试。批次历史保留发放人、配置、人数及有效期。

新建另一批会再次发放，因此不应在其他标签页另建批次来重试未确认的操作。

## 查看用卡情况

在「赠送额度卡」的发放记录中，点击对应批次的「查看用量」，可查看领取用户、邮箱、卡号、当前已用 / 总额度、账面剩余、状态和到期时间。支持按邮箱、用户名、用户 ID、卡号搜索及分页，默认包含过期或已撤销（含已删除）的赠卡。

点击单张卡的「明细」可分页查看该卡承担的每笔扣减、调用时间、请求 ID 与 API Key 编号；不会混入同一用户其他月卡或余额的扣款。重置已用额度会保留原扣费历史，因此历史合计可能不同于当前已用额度。已失效卡片的账面剩余不可继续使用。

两个查询入口仅对管理员开放，本次展示功能无需新增数据库迁移。

## 迁移与验证

迁移 `261_month_card_gift_batches.sql` 新增批次表及赠卡来源字段，允许赠卡没有付款订单和商品 ID，同时保留付费月卡的来源和 30 天周期约束。应先在包含现有月卡数据的备份环境演练迁移。应用该迁移后不要直接回滚旧后端：旧查询可能忽略无订单赠卡。

本地 PostgreSQL 测试通过独立 schema 验证资格、去重、并发幂等、原子回滚、跨周不重置、管理操作和真实结算。前端测试覆盖预览、确认、防重复点击、真实 409 错误结构、断线恢复、账号切换及卡包展示。

本地演示：在 `frontend` 目录运行 `pnpm exec vite --config vite.monthcard-gifts.config.ts`，打开 `http://127.0.0.1:18141/admin/group-buy`。该配置拦截所有 API，只写内存中的模拟数据，不连接正式服务器。
