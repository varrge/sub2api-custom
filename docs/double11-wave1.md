# 双十一第一弹：签到与趣味测验

## 范围

基于 `custom/0.2.17` 的 `237969082`。本次实现第一弹用户页面、系统设置功能开关、活动管理页签和任务发卡，不包含第二弹购买赠卡或第三弹寻宝。

- 页面：`/activities/double11`，登录后访问。
- 系统设置 → 功能开关 → 活动中心：`activity_campaigns_enabled`，默认关闭。控制导航、新参与和奖励领取；关闭保留参与记录和已发卡片。
- 系统设置 → 活动管理：管理第一弹启用状态、标题、副标题、正文、开放时间、目标摇摇卡活动 ID 和趣味题。
- 默认活动时间：北京时间 `2026-11-01 00:00` 至 `2026-11-06 00:00`（结束边界不含），即11月1日至5日。
- 日期按北京时间计算，与浏览器所在时区无关。

## 奖励

| 任务 | 奖励 |
|---|---|
| 首次签到 | 普通摇摇卡1张 |
| 累计签到3个不同日期，无需连续 | 普通摇摇卡1张 |
| 趣味题全部答对，允许重试 | 普通摇摇卡1张 |

三项各只能获得一次，每账号最多3张；不要求购买或调用。参与账号必须是有效个人账号。后台可配置3至10道题，每题2至6个选项。正确答案只保存在后台，用户接口不返回答案，提交由服务器判定。

默认测验包含鲸鱼赛跑、重量比较和表情猜成语；管理员可以在活动管理中替换题目。

日期和目标卡池在存在参与记录后不可修改。标题、说明、开关和题目仍可调整；管理保存使用版本校验，避免覆盖其他管理员的修改。题目变更后旧提交需刷新，不会清除已完成任务。

任务完成先记录奖励资格，用户点击领取后到账。未知发卡结果可重试，不能按失败直接补发。活动结束后不再签到或答题；已经获得但尚未领取的奖励，允许在活动开关保持启用、绑定卡池仍开放的情况下补领。运营应将卡池有效期覆盖活动及合理领取宽限期。

## 发卡接入

沿用原有 KaWang 摇摇卡，未新建独立库存。需要配套部署 KaWang 分支 `feat/double11-campaign-rewards`（提交 `aca9d9b`）的修改。

Sub 环境复用：

```text
NATIVE_BOX_SERVICE_URL=https://<trusted-kawang-service>
NATIVE_BOX_CONNECTION_ID=<this-sub-instance-connection>
```

管理员在活动管理中填入该连接下的摇摇卡活动 ID；该卡池需在领取时启用且处于有效期内。普通卡使用卡池现有奖品配置。Sub 不改变概率、奖品或月卡倍率。

启用活动时会检查卡池属于当前连接、状态为启用且有效期覆盖活动；卡池可以尚未开始。若预检失败则无法启用。领卡和摇摇卡页面使用短期服务端 SSO，不转发用户的浏览器 JWT；连接中保存的管理员密钥须与 Sub 当前的管理员 API 密钥一致。

关闭活动开关后不会批准新的发卡请求，但关闭前已经完成资格校验的在途发卡可能仍会完成。需要严格立即停止发卡时，应先在 KaWang 结束相应卡池，再关闭活动开关；结束卡池也会影响该卡池的其他用途。

流程：

1. Sub 事务记录签到/答题和唯一奖励资格，使用北京时间和服务器时间。
2. Sub 以已认证用户的 JWT 换取现有摇摇卡会话，会话只保留在服务端。
3. KaWang 使用该连接保存的 Sub 管理员凭据，查询管理员专用奖励接口，核对用户、任务、卡种、数量、活动开关和卡池归属。
4. KaWang 在同一 SQLite 事务中插入卡片和唯一发奖记录，重试返回原结果。
5. Sub 校验回执身份与数量后记录到账。网络丢失或本地记录失败不会重复发卡。

## API

用户接口沿用 JWT、面板限流和审计：

```text
GET  /api/v1/activities/campaigns/:id
POST /api/v1/activities/campaigns/:id/checkin
POST /api/v1/activities/campaigns/:id/quiz
POST /api/v1/activities/campaigns/:id/rewards/:task/claim
```

管理员专用：

```text
GET /api/v1/admin/activities/campaigns/:id
PUT /api/v1/admin/activities/campaigns/:id
GET /api/v1/admin/activities/campaigns/:id/rewards/:userID/:task
```

活动 ID 固定为 `double11-2026-wave1`。第二、三弹没有伪造为已实现的活动。
