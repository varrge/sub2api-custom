# 按模型管理密钥权限

已确认需求：用户在 API 密钥工具栏进入独立「按模型管理」页面，选择一个精确公开模型 ID，查看并修改自己全部未删除 Key 对此模型的权限。现有单 Key 编辑与新页面读取、写入相同的 `api_keys.model_allowlist`，没有模型到用户的独立授权表。

## 行为

- 默认按当前策略勾选。只显示至少一个已绑定、当前可用分组目录包含所选模型的 Key；多分组 Key 仅展示匹配分组。不匹配的 Key 不显示、不计数、不提交保存。搜索、分组筛选只影响这些符合条件 Key 的显示；保存包含被搜索或分组筛选隐藏的符合条件 Key。页面不显示密钥凭据。
- 模型列表沿用原有来源：合并当前用户可用分组目录、已保存模型及手动输入的完整 ID。选择目录没有列出的模型时右侧为空；目录加载不完整时，只显示已确认支持所选模型的 Key 和分组。已停用、过期仍单独标注；不再显示「目录未列出」或「目录待确认」行。
- 不限制 → 禁止某模型：启用 deny，名单只有该模型，不启用暂存的旧名单；allow 加入/移除所选模型；deny 移除/加入所选模型。其余模型及未来模型权限不变。
- 空的启用 allow 是禁止全部；关闭限制是允许所有。新建 Key 沿用其自身配置，不继承以前的批量操作。
- 有草稿时切换模型、刷新或离开页面需选择保存、放弃、留在原页。保存失败保留草稿；冲突需刷新核对。

## 接口与一致性

- `GET /api/v1/keys/model-access` 返回当前用户全部未删除 Key 的管理摘要、模型规则及策略修订值，最多 10000 把，不含凭据。
- `PUT /api/v1/keys/model-access` 接收 `{model, entries:[{id, revision, allowed}]}`。操作的是读出时的 Key 快照；后来新建的 Key 不自动加入，后来删除或修改策略的 Key 使保存返回 409。
- 后端按 ID 顺序加行锁，在同一事务内校验归属、比对策略修订值、逐 Key 更新规则。任何验证/写入失败回滚整批；只写模型配置和更新时间，不回写用量、分组、状态。
- 修订值针对 Key ID、归属和模型策略的摘要；用量和最后使用时间变化不制造冲突。现有用户及管理员单 Key 编辑也携带此值，旧客户端省略仍兼容。
- 提交后在独立有界 context 中清理鉴权缓存并广播，客户端断开不会取消这一步。现有网关的精确 ID 校验与模型目录过滤继续生效。
- 复用已有 JSON 字段，无新增数据库迁移。空 allow 行为改变在规范化与单 Key UI 中同步实现。
