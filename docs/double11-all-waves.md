# 双十一三弹活动

三弹共用 `/activities/double11` 页面和「系统设置 → 功能开关 → 活动中心」总开关，在「活动管理」分别配置启用状态、标题、说明、北京时间、目标摇摇卡卡池。新活动默认关闭。页面由 Gemini CLI `--yolo` 实现，业务和发卡逻辑由主代理接入。继续使用原鲸鱼娘 PNG 及其署名和许可。

| 活动 | 默认时间（北京时间，结束边界不含） | 奖励 |
| --- | --- | --- |
| 第一弹：签到与趣味答题 | 2026-11-01 00:00 至 11-06 00:00 | 首签、累计3天、答题通关各1张普通卡 |
| 第二弹：月卡拼团加赠 | 2026-11-06 00:00 至 11-12 00:00 | 见下表，每账号最多3张月卡参加 |
| 第三弹：全站寻宝 | 2026-11-12 00:00 至 11-16 00:00 | 找到3只鲸鱼1张普通卡；集齐5只再得1张 |

## 第二弹

| 月卡原价 | 购买赠卡 | 同团达到3个有效购买名额后追加 |
| --- | --- | --- |
| 58元 | 1张普通卡 | 1张普通卡 |
| 128元 | 2张普通卡 | 1张普通卡 |
| 198元 | 1张中级卡 | 2张普通卡 |

- 按可信支付订单的 `paid_at` 判断活动期，原价来自不可变购买快照；优惠后的实付额、商品后续改价不改变奖励档位。
- 同账号重复购买、自拼分别计数。单独购买可以获得购买奖励，没有拼团追加奖励。
- 已知的符合条件订单按付款时间、订单ID排序，最多前3张。更早已付款但暂未发出月卡的订单会预留名额；若最终退款且从未发出月卡，该订单不占名额。
- 已发出月卡后退款或被撤销，不再允许新赠卡，但不会空出已占用的活动名额。已发出的摇摇卡不会自动追回；退款时需人工核对已经使用的活动奖励。
- 极晚到达的支付通知不能替换已经确认的三个参与名额，避免回收已发奖励或突破上限。
- 成团按购买名额而非去重用户计数，且至少3个名额的付款时间必须早于团的招募截止时间。管理员删除且保留招募名额的月卡继续计入团人数，该月卡本人的未发活动奖励不再发放。
- 活动期间购买的月卡，所属团在其招募期限内达到3个名额，活动结束后也会追加奖励。已确认的成团结果不因其他团员后来退款而撤销。
- 后台任务每30秒检查、记录资格并尝试发卡；正常情况下约一分钟内到账，故障自动重试。用户可在活动页手动重试同一笔奖励。
- 总开关或第二弹开关关闭时不产生新资格、不批准新赠卡；重新开启时会检查配置活动期内的合格付款并补发。需要完全结束本活动时保持开关关闭。

启用第二弹时，卡池结束时间必须覆盖活动结束时间，加上当前适用商品/招募中团队的最长招募期（至少48小时），再加24小时补发缓冲。后续增加商品招募期或长时间暂停发卡时，运营也需要同步延长卡池有效期。卡池变更不由该页面自动执行。

## 第三弹

小鲸鱼出现在仪表盘、API密钥、使用记录、拼团大厅和个人资料页。活动页按天公布谜语线索，不提前列出完整答案。五只鲸鱼从活动开始起都可被找到；线索分四天开放，前两条首日开放，之后每天一条。

进入对应页面后，服务器签发绑定账号及该鲸鱼的10分钟随机令牌；点击后核对并持久化进度。重复点击、重复请求只记一次，不使用浏览器本地存储作为奖励依据。该机制阻止伪造鲸鱼ID、跨用户令牌和过期令牌，并不声称能证明用户进行了人工浏览。

找到3只、5只分别记录一次奖励，需在第三弹结束前领取。未参加前两弹也可参与。仅有效个人账户参加，企业账户不展示寻宝入口，也不能通过接口领取。

## 发卡和部署

Sub迁移259扩展现有奖励表，增加购买参与名额和寻宝进度；迁移260增加团级三人里程碑，发月卡时在同一事务记录，避免退款和扫描顺序影响其他团员的追加奖励。已有第一弹记录不变。奖励资格中保存卡种、数量和原始订单；KaWang通过保存的Sub管理员凭据核对精确资格，再在单一SQLite事务内插入1至2张卡及唯一奖励记录。

先部署配套 KaWang，再部署 Sub。三弹配置应使用同一个覆盖完整活动及补发窗口的共享卡池；KaWang既有规则不允许同连接的卡池时间重叠，不能分别建立时间重叠的第二、三弹卡池。KaWang兼容旧第一弹发奖记录，并支持三弹的受限任务、卡种、数量；重复请求读取原回执，即使卡已使用也不再发放。用户无法提交用户ID、卡种、数量或卡池来覆盖后端配置。

自动发卡与用户手动领取共用同一条短期服务端SSO及发卡路径。网络响应丢失后重试相同奖励键；Sub仅在身份、活动、卡池、任务、卡种和数量全部相符后记录到账。

开关关闭或退款完成前已通过资格校验的在途发卡仍可能完成。严格立即停止发卡需先在KaWang结束目标卡池；这也会停止同一卡池的其他发卡用途。

后台活动配置采用版本号防止覆盖。任一参与记录出现后，时间和卡池锁定；可继续改文案、第一弹题目和启用状态。三弹默认时间独立，不改月卡价格、额度或优惠券。

## 新接口

原有活动状态、领取、管理员读写接口接受三弹ID：

- `double11-2026-wave1`
- `double11-2026-wave2`
- `double11-2026-wave3`

新增个人账户接口：

```text
POST /api/v1/activities/campaigns/double11-2026-wave3/treasure/visit
{"path":"/keys"}

POST /api/v1/activities/campaigns/double11-2026-wave3/treasure/find
{"id":"key","token":"<服务器签发的令牌>"}
```

状态增加 `purchases`、`treasures` 数组及奖励的 `card_tier`、`quantity`。第一弹签到和答题接口拒绝其他活动ID。
