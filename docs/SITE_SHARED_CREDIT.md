# 全站共享额度

管理员在 **系统设置 → 共享额度活动** 设置活动名称、开始／结束时间、开关、累计总额度与适用分组，并查看消耗明细。也可以在 **分组管理 → 编辑分组** 单独保存该分组的参与状态。初始状态关闭、预算为 0、没有参与分组。

## 临时活动与余额门槛

开启活动必须填写结束时间；开始时间留空表示开启后立即生效。到开始时刻可参与，到结束时刻停止新增补贴，无需依赖定时任务。时间输入显示管理员浏览器时区，保存为带时区的绝对时间。页面展示已停用、未开始、进行中、已结束等已保存状态。

余额低于 0 元的用户必须先充值至 0 元或以上才能发起调用，包括使用共享额度。余额为 0 时可参与有效的共享活动。准入以数据库当前余额为准，不依赖认证缓存或月卡模块是否配置；固定费用／批量预留同样拦截欠费。已发生的调用仍记账，结算时已欠费不再获得新增共享补贴；此前接受的预留继续履约。

## 顶栏快捷显示

登录后的顶栏在个人余额左侧显示全站共享剩余额度。点击可查看活动时间、本人已获授权的参与分组、原价 USD 扣减规则及负余额充值提示。未开始、进行中及已耗尽的活动可展示；关闭、配置不完整、未选分组或活动到期时隐藏。

摘要接口为 `GET /api/v1/user/shared-credit`，需要用户认证，只返回活动摘要及授权分组交集，不返回管理版本、全部分组或消费明细。额度每分钟自动刷新，回到页面、展开详情或手动刷新时也会更新；请求失败显示未知金额。活动结束按服务端时间校准后在页面隐藏。此处金额是全站共享的模型原价 USD，个人余额仍在右侧独立显示。

## 扣费规则

- 共享额度按模型原价 USD 扣减，不乘用户或分组倍率。适用分组内的已授权调用先用共享额度，包含月卡、订阅和企业用户。
- 不足部分恢复原有月卡／订阅／余额扣费顺序。例如模型原价 $10、用户倍率 0.3x、共享剩余 $4：共享扣 $4，个人支付 `(10−4)×0.3=$1.80`。
- 总额度是累计预算。总额从 1000 改到 1500 表示追加 500，已用不会清零；总额不能小于已用加预留。
- 共享额度不授予分组访问权；有效期、冻结、封禁、欠费、Key 限额和平台限额仍按原规则检查。Key／上游／适用的平台用量仍计完整调用费用。
- 不选分组不会补贴任何调用；未勾选分组保持原扣费方式。

## 结算与管理

普通调用按结算时可用共享额度分配；共享与个人扣款在同一数据库事务内提交，请求重试不会重复扣款。并发调用耗尽共享额度后，未覆盖费用按原规则向用户结算。

固定费用和新创建的异步批量任务提前预留共享额度，成功后结算、取消后归还。关闭开关、活动到期或移除分组后，已接受的预留仍用于对应任务，不会额外申请新补贴。升级前已创建的批量任务沿用原计费快照。

配置保存使用版本校验。其他管理员修改后会提示重新载入，避免覆盖他人的设置。消耗明细同时显示扣减的模型原价额度与免除的个人支出。

迁移：`backend/migrations/262_site_shared_credit.sql`、`263_site_shared_credit_activity.sql`。上线迁移不会自动开启功能或增加预算。未填写结束时间的旧配置不参与补贴，需管理员补全活动时间。

固定费用账单失败后会持久化重试。平台用量沿用现有缓存／刷盘机制：SQL 结算提交后到平台用量更新之间的进程崩溃窗口仍存在，未在本功能中重构。
