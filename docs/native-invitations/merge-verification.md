## 接入

- 用户入口 `/invitations`，管理员入口 `/admin/invitations`。
- 一次性邀请码、申请配额、用户等级、有效期、分享链接。
- 邮箱注册和六种 OAuth 提供商携带邀请码，账号创建和邀请关系一起提交。
- 首次正数余额充值记录返利快照；后续充值及通用 affiliate 不重复奖励。
- 管理员审核、拒绝、撤销和可选延迟自动入账；变更有审计记录并失效余额缓存。
- 新迁移为 `270_native_invitations.sql`，不修改已经发布的迁移。
- 默认关闭新码申请、自动审核，初始返利比例为 0。

## 适配与修复

- 保留最新注册邮箱限制、确认密码、验证码、管理员二次验证和部署安全控制。
- 后台设置、指定等级、禁用邀请码及返利审核都要求二次验证，页面支持验证后重试和取消。
- 开放注册时仍可验证、使用主动提供的邀请码；过期码不能通过预验证。
- 自动入账在事务中重新核对等待时间、配置、账户和支付状态；按账户、配置、订单的顺序加锁，避免与退款锁顺序冲突。
- 禁用、删除或转企业后的用户仍可取消指定等级，避免永久阻止删除等级规则。
- 浏览器存储失效时，在当前页面内保留申请幂等键，网络失败重试不会多领邀请码。
- OAuth 请求区分未提供与主动清空邀请码；隐藏输入框不覆盖后端保存的邀请关系。
- 补齐原充值单测的 SQLite 邀请关系表；保留生产环境缺迁移时的错误处理。
- GitHub Actions 增加独立 PostgreSQL 邀请与返利测试步骤，启用竞态检测并配置两个测试 DSN。
