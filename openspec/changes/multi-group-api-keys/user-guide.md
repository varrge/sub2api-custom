# 一把密钥使用多个分组

在「API 密钥」中新建或编辑密钥，依次添加自己有使用资格的分组。列表顶部优先；使用上下箭头调整顺序。管理员在用户的密钥管理中也能代为配置，候选范围仍是该用户已有资格的分组。

客户端继续填写同一把 API 密钥。每次独立请求由服务根据模型、接口和分组顺序选择可用组。不匹配、暂时没有可用账号、订阅过期、额度耗尽或权限撤销的组会被跳过。排在后面的组可能更贵，也可能直接扣余额，因此请按实际需求安排顺序。

- 一次请求按一个实际分组计费；不同组的订阅/月卡额度保持独立。
- 密钥总额度及 5 小时、1 天、7 天消费限制累计所有组，换组不会重置。
- 暂时不可用的组会保留在列表里，恢复资格后重新参与选组；删除分组会移除其绑定。
- 原密钥字符串、有效期及限额不因增加分组改变。
- 启用过多分组的密钥，其兜底范围始终限于已选且有资格的组，即使以后只保留一个组。

Responses 续传和长连接继续使用会话原分组，无法继续时明确报错，需要新建会话。已创建的图片、视频和批量任务按原归属查询；密钥或用户被停用后仍会禁止访问。

模型列表合并有资格的组并去重。透传模型不以目录为白名单；模型没有出现在目录里，不代表一定不能调用。
