# 仅在模型受限时定时测试

## 行为

账号的「定时测试」新增 `only_when_model_limited` 开关，创建、编辑均可配置，默认关闭。旧计划保持原有 Cron 行为；旧客户端更新时不传此字段会保留当前值。

- 开启后，在下一次 Cron 时间检查所选模型及账号是否存在有效的上游限流。没有限流时待命，只推进下一次检查时间，不发请求、不生成结果、不修改最后测试时间。
- 账号须处于启用、可调度且未因到期自动暂停的状态。API 密钥的模型允许/禁用列表不是触发条件。
- 开启「自动恢复」后，探测成功只清除探测前观察到且未被并发更新的对应模型/账号限流。其他模型、手动暂停、临时禁用和其他状态保留。
- 实际探测模型必须与观察限流时解析出的目标一致；映射变化或缺少目标信息时保留限制并记录失败。
- 恢复后自动待命，再次限流时继续按计划测试。关闭「自动恢复」则只记录结果，不主动解除限制。
- Antigravity 的此类探测绕过本地模型冷却拦截，但不启用付费积分兜底或收到响应后的重试，防止把兜底成功误判成配额恢复。正常网关请求不受影响。

## 实现

迁移 `246_scheduled_test_only_when_model_limited.sql` 添加默认 `false` 的布尔列。恢复使用单条 SQL 对观察到的完整 JSON 限流条目和账号限流时间做比较后删除，并同步调度快照。Cron 阻止单个进程内的扫描重叠；没有新增跨实例分布式锁。

探测使用与路由一致的模型映射，并识别 Bedrock、Vertex 和 OpenAI OAuth 的上游模型名称。OpenAI 图片探测修正了重复应用映射的问题。

## 验证

- 后端定向回归：待命→受限→探测失败→成功恢复→待命→再次受限；保留更新后的限流、其他模型和不可调度状态。
- 使用实际 AccountTestService 验证 Antigravity 200/429 均只请求一次且无付费兜底、Gemini 通配符映射和 OpenAI 图片单次映射；上游为本地替身，不调用真实供应商。
- 隔离 PostgreSQL 验证迁移、CRUD、旧计划默认值、待命时间以及比较后清理。CI 集成测试已配置相同的数据库测试入口。
- 前端组件和中英翻译完整性测试、类型检查、生产构建、定向 ESLint、后端构建及定向 golangci-lint。
- Chromium 验证桌面/手机、浅色/深色的创建、保存、重新编辑与开关回显；页面 API 为本地替身。计划标题及状态标签在窄屏下自动换行。
- 独立代码复审通过；此前发现的探测拦截、恢复范围和模型映射问题已修复并覆盖回归。

## 发布与回滚

本次仅实现并本地验证，未部署服务器、未创建新 tag。

迁移可兼容旧程序读取，但旧程序不会识别条件开关，会把启用的条件计划当作普通 Cron 计划执行。回滚到不支持此功能的程序之前，必须停用 `only_when_model_limited = true` 的计划并保存清单，待回到支持此功能的版本再恢复。不可直接将该字段改成 `false` 作为回滚措施。
