# v0.2.25-custom.5

基于 v0.2.25-custom.4，新增 Sub2API 原生摇摇乐，保留现有管理员安全通知、IP 永久封禁与解除封禁功能。

## 更新

- 摇摇乐由 Sub2API 本地管理活动、发卡、抽奖和余额发奖，不再连接卡网服务。
- 后台可配置订单/实际消耗发卡规则、三档卡片奖池、手动补发、抽奖作废和消费榜自动奖励；用户可查看规则与获取进度。
- 双十一任务奖励改用本地发卡；切换旧活动时只重绑未发放奖励，已发放任务不重复发卡。
- 抽奖扣卡、发奖和余额流水在同一数据库事务中完成，支持重复请求和断线后的结果恢复。
- 修复原生月卡消耗分类、活动规则变更导致历史重复发卡、活动延期与到期/恢复查询的竞争；月卡购买阈值按人民币展示。
- 新增迁移 `275_native_shake.sql`，只建立原生数据表，不导入卡网历史活动、卡片或抽奖记录。发布 CI 增加 PostgreSQL 发卡、抽奖和活动奖励回归测试。

## 升级与切换

1. 停止卡网针对本站的摇摇乐及相关发奖任务，避免两套系统同时发放奖励。
2. 更新服务后，在「摇摇乐管理」中新建并启用活动；旧 `NATIVE_BOX_SERVICE_URL` / `NATIVE_BOX_CONNECTION_ID` 已不再使用。
3. 按需重新绑定双十一活动和消费榜奖励。未启用新活动时，用户页显示暂无活动。
4. 如需补偿旧卡片，通过管理员手动补发；历史数据不会自动导入。

沿用 custom.4 的 IP 封禁配置要求：反向代理部署须正确设置 `SERVER_TRUSTED_PROXIES`。

实现与本地验证说明见 `docs/native-shake/implementation.md`。推送 tag 后由 GitHub Actions 执行 CI、安全扫描和构建发布，不自动在生产服务器启用摇摇乐活动。
