# 0.2.17-custom.8

修复 `v0.2.17-custom.7` 发布被 integration 测试阻止的问题，包含该版本的企业模式、特权规则与四种欢迎动效。

- `TestRedeemConcurrentReductionsBothApply` 原来在读取订阅后等待两笔兑换同时就绪；企业身份保护新增的用户行锁会让同一用户的两笔兑换串行执行，因此第一笔被测试钩子阻塞，第二笔无法取得用户锁，十秒后必然超时。
- 将共同启动门移到进入兑换事务之前。保留两笔均成功、订阅合计扣减两天、两个兑换码审计备注、两次订阅锁定读取的断言；相邻的续费交错回归保持不变。失败路径先取消上下文并等待 worker 退出，再清理数据库夹具。
- CI 的完整 integration 步骤新增 `ENTERPRISE_TEST_DSN`，复用隔离 PostgreSQL 服务，确保企业转换、冻结月卡和对账测试不因缺少环境变量被跳过。发布策略测试约束该设置及完整测试命令。

未更改生产计费逻辑、身份锁、数据库迁移或发布门禁；未删除测试、跳过失败或延长超时。`v0.2.17-custom.7` 保持原指向，补发新 tag。

升级仍包含企业迁移 256；已有企业身份及折算数据的数据库不可直接回退至不识别企业限制的旧程序。源码/制品发布不代表服务器切换。

本地验证：

- 原失败用例在修改前再次稳定复现；修改后并发扣减与续费保护测试连续 20 轮通过，并在 race 检查下连续 20 轮通过。
- 与 CI 一致的 `make test-integration` 全量通过，显式设置 scheduled、activity、model-access 和 enterprise 的测试数据库连接；后端默认及 unit 全量测试通过。
- 真实 PostgreSQL 月卡全套 race 与 EasyPay webhook race 测试通过；`go vet`、golangci-lint 2.14.0（0 issues）通过。
- 前端沿用 CI 的完整 lint、类型检查和关键测试（55 文件、861 项），i18n 与生产构建通过；Linux amd64 嵌入构建通过。前端功能没有改变，本轮未重跑其全部 3499 项用例。
- 独立代码复核通过；发布策略、10 项发布辅助脚本测试及 Compose 简单模式环境检查通过。
