# 企业欢迎提示与特权设置（2026-10-21）

用户选定方案 A：顶部暖金胶囊。UI 由 Kimi K3 YOLO 实现，主代理负责配置、资格判定、播放生命周期与集成。

## 当前已实现

- 管理员 → 系统设置 → 特权设置：企业欢迎提示开关、文案、预览、独立保存。默认开启，文案为“欢迎尊贵的企业用户”。
- 文案为 1–80 个 Unicode 字符的单行纯文本；禁止控制字符，按文本转义展示，不接受 HTML。读取失败时提供重试，不以默认值覆盖已有配置。
- 企业非管理员整页打开、刷新、重新登录时播放一次；站内切页及资料刷新不重播。退出、换号、卸载取消旧请求和定时器。
- 等待 350ms、入场 400ms、停留 3500ms、退场 250ms；支持手动关闭、移动端、明暗主题和减少动态效果。原型的 A/B/C 切换条不进入正式 UI。
- 配置复用 settings 表的 `privilege_settings` JSON，无数据库迁移。管理接口 `GET/PUT /api/v1/admin/settings/privileges`；用户接口 `GET /api/v1/user/privileges` 只返回当前用户实际可见的头衔与欢迎文案，资格以服务端用户身份为准。
- 用户接口属于展示信息，不参与授权或计费，不改变企业倍率、充值、分组、余额、月卡或活动规则。

## 普通用户多条件头衔（本轮追加）

用户明确要求普通用户也在同一个「特权设置」配置，且条件不限于消费。企业欢迎配置保留，同页新增普通用户规则列表。规则默认空，不会自动给现有用户套用档位；管理员添加、编辑、启停、排序、删除后统一保存。

| 条件 | 口径 |
| --- | --- |
| 累计 API 消费 | 当前用户保留使用记录的 `actual_cost` 总和，USD；包含套餐抵扣的 API 用量，不是现金实付。已清理历史无法补算。 |
| 累计充值入账 | 当前用户已完成余额充值订单的 `amount`，USD；包含订单创建时倍率，扣除成功全额/部分退款。退款申请/处理中/失败不提前扣减。排除未完成订单、赠送、返佣、兑换码、订阅/月卡和月卡折算；不是不同币种的网关 `pay_amount`。 |
| 注册时长 | 注册至今的完整 24 小时天数；零时间或未来注册时间不达标。 |
| 管理员指定用户 | 按现有普通用户 ID 指定；后台校验存在、未删除、非管理员、非企业。 |

- 每条规则配置启用开关、头衔名称（1–24 Unicode 字符）、条件及门槛/用户 ID、欢迎动效开关和文案。关闭欢迎仍可显示头衔。文本禁止控制字符和行分隔符，前后端按 Unicode code point 计数。
- 最多 50 条规则；每条手动规则最多 200 位用户，整个配置最多 1000 个不同手动用户。金额门槛正数、上限 1e12；注册时长为 1–365000 整数天。
- 优先级从上到下，首条匹配即停止，只显示一个头衔；不同条件的数字不互相比大小。消费高档应由管理员排在上方。企业与管理员不参与普通规则，头衔不改变企业身份、余额、倍率或分组权限。
- 每次整页/重新登录按最新数据匹配；规则关闭/删除、成功退款、使用记录清理等可能撤销资格，不是永久授予。头衔在用户信息和个人资料展示；欢迎仍复用方案 A。
- `privilege_settings` JSON 增加 `personal_rules`，无迁移或新依赖。旧 enterprise-only 配置仍可读取；旧客户端保存省略或 null 的 `personal_rules` 时保留当前规则，仅显式 `[]` 才清空。
- 用户接口仅返回当前用户命中的 `title` 和 `welcome`，不暴露规则或其他用户 ID，使用 `Cache-Control: no-store`。身份类型/角色改变、换号、退出清空头衔并取消旧请求；晚到响应不得串号。

不包含现金奖励、自动折扣、分组权限、每日签到/邀请任务、永久成长积分或复合 AND/OR 规则；这些会改变账户权益或需要额外可靠事件数据，不在本轮展示型特权范围。

## 可选欢迎动效（2026-10-22 扩展）

企业欢迎和每条普通用户规则可分别选择，不共用全站唯一效果：

| 值 | 方案 | 表现 |
| --- | --- | --- |
| `capsule` | A · 暖金胶囊 | 保留顶部轻落胶囊与一次金色高光。 |
| `slide` | B · 侧滑卡片 | 右上角身份卡平滑滑入，手机端自适应。 |
| `halo` | C · 光环徽章 | 顶部中央徽章轻缩放、一次光环扩散。 |
| `ribbon` | D · 流光横幅 | 顶部横幅展开、一次流光扫过。 |

- `enterprise_welcome.effect`、`personal_rules[].welcome_effect` 存储独立选择，用户响应 `welcome.effect` 只携带实际命中规则的值。仍只影响展示，不改变资格或计费；关闭欢迎时仍保留选项，普通头衔照常显示。
- 旧存储缺少字段时默认 A；旧客户端保存省略新字段时保留当前企业选择和同 ID 规则的效果，排序不影响关联，新规则默认 A。明确传 `capsule` 才改回 A；未知值服务端拒绝。公开响应中的缺省/未知效果在前端安全降级 A。
- 选择和预览是本地草稿，不自动保存；与原配置一起提交。预览和实际播放使用同一组件、相同生命周期（350ms 等待、400ms 入场、3500ms 停留、250ms 退场）。重复预览替换上一次的计时器。
- 全部效果可手动关闭，无声音、闪烁、循环和全屏遮罩，不阻拦其他业务操作；手机、深浅主题及系统“减少动态效果”受支持。退出/换号/卸载清理效果状态和定时器，站内切页不重复播放。
