# API 密钥多分组

状态：Q1～Q20 全部确认，用户已授权开始实现。日期：2026-09-18。

## 已确认规则

1. 客户端配置一把密钥；服务按请求模型、接口和该密钥的分组顺序自动选择。
2. 用户与管理员均可配置，只能选择密钥所属用户已有资格的组；管理员代配置不授予权限。
3. 允许跨平台、订阅、余额、Composite 分组混选，提供有序多选。
4. 一次请求归属一个实际分组，沿用该组价格和同组权益结算；不同组不共享月卡额度。
5. 密钥总额度、5h/1d/7d 窗口累计全部组消费；账户限制继续生效。
6. 新调用发送前跳过不匹配、过期、额度耗尽、停用、撤权或没有可用账号的组；允许使用已选的更贵或余额组，页面告知。全部失败应提供原因。
7. 无法提前确定能力的透传组按排序参与，模型列表不作为调用白名单。发送上游后不新增跨组重发，流式输出不切组，沿用组内重试。
8. 暂时失效的组保留绑定和顺序，恢复资格后自动参与；删除组移除绑定。
9. 模型目录合并当前接口兼容且仍有资格的组，同名去重，临时额度耗尽不隐藏。
10. 旧密钥原组变单元素集合，字符串、额度、有效期保持；编辑即可扩组。
11. 从未启用多分组的旧密钥保留既有兜底。启用过多分组后，兜底也只能在已选有资格组内；缩回单组不恢复旧权限边界。
12. 新会话自动选组；previous_response_id、WebSocket、Realtime、Live 固定原归属，不可用时明确报错，不默默切组。
13. 已有图片/视频任务保留创建时的归属和计费快照；余额不足、订阅过期、排序变化、解绑原组仍可查询；停用密钥或用户仍拦截。
14. 新字段 group_ids 按顺序提交；旧 group_id 映射为单元素集合；同时提交报错；更新省略保持不变；空数组解绑全部仅管理员允许。
15. 保留现有管理员未分组密钥及 allow_ungrouped_key_scheduling 规则；普通用户新建/编辑须至少选择一个组。
16. 每次用量记录实际组，按组展示消费；密钥额度显示合计。按分组筛选密钥需匹配任意已选组。

## 实施边界

- 当前 custom/0.2.0 工作区已有月卡、拼团、支付改动；保留并在其基础上集成，不重置或混入无关修复。
- APIKey.GroupID / Group 保留为兼容投影和请求实际组，新增 GroupIDs / Groups 为配置集合，MultiGroupEnabled 为不可逆的权限模式标记。
- 每次选组产生请求私有对象，不能修改共享鉴权缓存。每个候选的权限、权益、价格和 RPM 覆盖必须独立加载。
- 管理员批量换组保留其他绑定与顺序、去重，沿用仅已有资格的授权边界。
- 资源操作按原资源归属处理；普通带完整历史的独立请求可重新选组。
- 数据迁移只增量扩展；保留旧 group_id，验证旧程序退回首组选组的降级行为及其限制。
