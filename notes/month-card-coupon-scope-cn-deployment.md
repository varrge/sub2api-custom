# 支付优惠码：多商品范围与每人不限次数

2026-09-24，用户要求适用月卡商品支持多选，并询问每人次数 0 的行为。旧实现前端最小值、后端校验与数据库约束都要求每人至少 1 次；本次统一支持 0 表示不限，默认仍为 1。

## 最终行为

- 新增和编辑优惠码支持全部月卡或指定多个商品，搜索筛选不清除已选项，列表展示所有适用商品。指定模式空选会阻止保存，切换全部才保存空数组。
- `product_ids` 为商品范围，显式空数组代表全部；省略该字段时兼容旧 `product_id` 输入。保留代表商品 `product_id`，采用排序后第一个 ID；后端逐个检查商品存在，去重排序，最多 1000 个。
- 总次数与每人次数均支持 0 为不限，各自独立生效；同一优惠码跨所有适用商品共享次数。每人限 1 次表示在全部适用商品中累计 1 次。
- 仍按原规则暂占未支付订单次数、释放取消或过期占用、保留已兑换次数（退款不返还）。下单事务重新检查商品范围及报价，已保留占用的旧订单按原报价履约。
- Kimi 使用 YOLO 模式处理模板及中英文文案，主代理处理脚本、存储、校验与测试。

## 数据与兼容

新增迁移 `248_month_card_coupon_product_scope.sql`：为已有全部商品优惠码回填空数组，为已有单商品优惠码回填单元素数组；允许每人次数为 0，保留默认 1。旧迁移文件未修改。

迁移触发器同步旧应用只写 `product_id` 的新增及范围修改，防止临时回滚后再次升级扩大范围。应急回滚只切换应用、不恢复覆盖数据库，但有功能降级：旧应用只识别代表商品；每人次数为 0 的新优惠码在旧应用会被判为次数已满，迟到支付重新占用也可能受影响。需要完整新语义时应向前修复。
