# 按模型选择密钥分组

## 使用方式

在「API 密钥 → 按模型管理」选择模型后，每个 Key 下的分组标签可直接勾选。只显示当前目录支持这个模型、且已绑定到该 Key 的分组；没有支持分组的 Key 不显示。

- 保存后，该 Key 调用当前模型时只能使用勾选的分组；调度顺序沿用 Key 原有的分组顺序。
- 单独调整分组也会显示待保存状态，可与其他 Key 的模型开关一起批量保存。
- 取消最后一个勾选会关闭该 Key 对该模型的调用。单独关闭模型开关保留勾选；重新开启时，若没有勾选则选中当前全部支持分组。
- 搜索和筛选保留被隐藏 Key 的修改。离开页面或切换模型时沿用保存、放弃、取消提示。
- 未修改的隐藏/暂时不在目录内的已保存分组规则不被覆盖；主动修改勾选则保存当前勾选集合。
- 历史 Key 未配置某个模型的分组规则时，继续使用原有调度行为。配置一旦存在，新增绑定分组不会自动加入该模型的已选集合。

## 数据与接口

每个 Key 独立保存 `api_keys.model_group_routes`，例如：

```json
{"gpt-6-astra":[2,5]}
```

模型 ID 是客户端使用的公开名称，精确匹配且区分大小写。没有对应属性表示沿用原有分组范围；显式空数组表示禁止该模型。规则与 Key 的模型总权限、当前绑定分组以及分组资格/模型策略取交集，不授予新的订阅资格，也不改变共享计费与限流计数。

`GET /api/v1/keys/model-access` 的 Key 快照增加 `model_group_routes`。现有 `PUT /api/v1/keys/model-access` 每条 entry 可选增加 `group_ids`：

```json
{
  "model":"gpt-6-astra",
  "entries":[
    {"id":10,"revision":"<返回的 revision>","allowed":true,"group_ids":[2,5]}
  ]
}
```

省略 `group_ids` 保留原规则，兼容旧客户端。只对修改勾选的行发送此字段；未修改行仍参与 revision 校验。后端拒绝重复、非正数或不属于 Key 的分组，以及 `allowed:true` 配空分组。每把 Key 最多保存 512 个模型的分组规则。

事务按 Key ID 加行锁，校验所有权与 revision 后一起写入。revision 包含模型权限、绑定分组及模型分组规则；并发编辑冲突返回 409，整批不部分提交。原有单 Key 模型编辑保留该列；仅调整分组规则也在提交后失效认证缓存。认证快照版本为 v29，转换及 `ForGroup` 深拷贝规则，避免共享引用污染。

## 路由检查

- 多分组路由在准入、探测及计数前跳过未勾选分组；选中组故障或限流时不扩大范围。
- 固定资源分组及后续 WebSocket 请求使用原公开模型检查当前规则；新 turn 不能借用先前会话绕过新设置。
- 单分组 Key 的调度也固定分组，避免 Claude Code 自动降级越过勾选。显式网关 fallback 同时校验公开模型规则和原有目标组策略。
- Live 和图片请求省略模型时，在选组前分别按实际默认模型 `gpt-live`、`gpt-image-2` 检查；顶层 Live 提示和图片的嵌套 session 不替代实际默认模型。
- Live 创建及 Sideband 重连检查固定模型的当前分组权限。已归属用户的历史资源读取保留原有所有权规则。
- 普通模型目录、Codex、Gemini 及批量生图目录按来源分组过滤后再合并，保留允许来源的元数据。

## 迁移与发布边界

迁移 `251_api_key_model_group_routes.sql` 添加 JSONB 非空列，默认 `{}`，不改写旧权限或计费数据。Ent schema、认证投影及 API DTO 同步增加该字段。

旧二进制忽略此列，因此回退旧版本会停止执行这些分组限制；不能将数据库向后兼容等同于权限语义向后兼容。发布时所有承接流量的实例应使用支持本规则的版本。

本次实现位于 `feat/model-group-routing`，尚未部署、合并或打 tag。
