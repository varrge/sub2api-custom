# 企业用户模式方案

状态：已按用户第三轮反馈实施，前后端集成、最终构建和测试完成。日期：2026-10-21。具体实施边界和验证记录见 implementation.md。已按追加授权部署中国独立验收站，见 deployment-cn.md；未提交或正式发布。

目标：管理员在用户管理中将指定账户设为企业用户，账户固定进入企业界面，按该用户在各分组的企业倍率消耗余额，停止参与平台活动。

实现分工：UI 交给用户指定的 **kimi-k3，YOLO 模式**；账户权限、路由限制、接口契约、计费、支付、迁移和集成验证由主代理负责。用户已授权开始开发。

## 1. 已明确的需求

1. 管理员可以在用户管理中设置企业用户。
2. 企业身份由管理员控制，用户不能手动切换为普通用户或普通界面。
3. 企业用户不参与拼团月卡、订阅、优惠码、兑换、邀请返利等活动。企业充值倍率独立，默认 1，不参与普通用户的充值倍率；渠道与支付流程复用现有能力。
4. 企业界面最多保留六项业务入口：使用记录、渠道状态、API 密钥、充值余额、个人资料、我的工单。支付关闭时隐藏充值入口，工单未开启时隐藏我的工单入口。
5. 管理员可以为每个企业用户配置各分组对应的企业专属倍率；未设置时沿用该用户当前适用的倍率，不因缺少企业报价而禁止调用。
6. 转换时的折算弹窗仅适用于当前有拼团月卡套餐的用户。服务端自动识别该用户所有有效月卡的剩余总额度，按管理员设置的折算倍率计算余额，确认后折算并切换身份；不折算旧订阅，不提供人工核定旧订阅额度。
7. 企业用户每次打开模型广场默认选中“仅看企业用户倍率”，仅显示为该用户设置了企业专属倍率的分组；未设置的不显示。取消选择后恢复普通用户的分组倍率查看，实际调用计价规则不变。
8. 低余额提醒复用现有能力；月度对账导出纳入本期范围。

下文的标注为“建议”的规则用于补齐实现细节，不代表用户已经确认。

## 2. 推荐的第一期产品行为

### 2.1 身份与界面

- 新增账户类型 `account_type = personal | enterprise`，现有用户默认 `personal`。继续使用现有 `role` 表达管理员权限；企业类型不授予管理权限。
- 建议第一期仅允许普通角色账户设为企业用户；管理员用独立测试账户验收企业模式，避免账户类型与管理权限混用。
- 登录、会话恢复、资料刷新均从服务端获取账户类型。企业身份不能由网址参数、浏览器缓存或个人资料修改接口决定。
- 企业没有“切回普通版”入口；保留深浅色、语言、退出登录等基础操作。
- 建议默认落地页为“使用记录”，在页头展示余额与当期消费，不新增第七个“企业仪表盘”入口。
- 已登录账户被调整类型后，后端立即按新规则处理后续新操作；前端在资料刷新、重新聚焦及收到权限变化错误时同步切换。加载身份期间不闪现普通活动菜单。
- 不复用部署级 `run_mode=standard|simple` 作为企业身份。企业模式与普通用户同时存在，原有站点级开关继续约束功能是否可用。

### 2.2 六个入口

| 入口 | 企业用户可以做什么 | 建议复用的位置 |
| --- | --- | --- |
| 使用记录 | 查看、筛选用量和消费，按月、分组、API Key 导出对账数据 | `/usage` |
| 渠道状态 | 查看自己获准分组的状态，提供前往模型广场查看报价的入口 | `/monitor` |
| API 密钥 | 创建、查看、编辑、停用、删除自己的密钥，只绑定获准分组 | `/keys` |
| 充值余额 | 普通余额充值、到账预览、查看充值订单和支付结果 | `/purchase`，订单及支付页作为其子流程 |
| 个人资料 | 资料、安全设置、密码、身份绑定、通知邮箱 | `/profile` |
| 我的工单 | 提交工单、回复、查看进度和附件 | `/tickets` 及其子页面 |

“只有六项”指业务导航。支付扫码页、第三方支付返回、订单详情、工单详情、身份验证等必要流程继续开放，不增加一级入口。订单入口归入“充值余额”；历史消费和财务记录不删除。服务公告可保留，活动推广横幅不展示。

模型广场按本轮要求允许企业用户访问；建议从渠道状态中的“模型与报价”按钮进入，保留六个一级入口。它是报价查看页面，不能借此购买订阅或参加活动。

普通仪表盘、拼团大厅、我的订阅、邀请返利、兑换、在线生图、批量生图面板、自定义推广导航不进入企业工作台。已登录企业账户通过旧收藏或直输网址访问受限页面，跳转至使用记录并给出说明。支付和身份验证回调优先完成流程，不能被统一重定向打断。

这不等于关闭模型 API：获准分组中可正常计费的文本、图片等 API 仍可通过密钥调用；网页入口和模型调用权限分开判断。

工单、支付、监控依赖现有全局开关，不通过企业身份绕过全站停用设置。按用户最新要求，支付关闭时隐藏企业充值导航；工单未开启时隐藏企业工单导航。已有路由和后端权限检查继续生效。

### 2.3 活动隔离

企业账户禁止：

- 购买或领取旧订阅、独购月卡、发起拼团、加入拼团及拼团升档权益。
- 使用优惠码、促销码、额外活动赠额、普通用户充值倍率和用户自助兑换入口；正常余额充值使用独立的企业充值倍率，默认 1。
- 获取新的邀请奖励或充值返利；企业充值也不给邀请人产生返利。
- 通过管理员代建密钥、默认订阅分配、后台补发活动权益等路径绕过企业规则。

企业仍允许管理员正常调账、在线余额充值、退款、历史记录查询和工单处理。管理员调账沿用现有审计和备注，不伪装成活动赠额。

建议邀请关系和历史返利账本保留，停止新增返利、绑定和转入；已有待结算返利在转换弹窗中单独提示，不混入套餐折算。历史退款或对账修正仍能冲正原流水。

限制要同时落在前端路由、后端受限端点以及业务动作发生处。支付履约、返利结算等无用户浏览器参与的路径也必须校验。前端隐藏入口不能作为权限判断。

## 3. 企业分组与消费倍率

### 3.1 管理员操作

在“用户管理 → 编辑用户”中增加账户类型和企业配置区：

| 分组 | 开放给此用户 | 企业倍率 | 示例 |
| --- | --- | --- | --- |
| 分组 A | 是 | 0.60 | 基础费用 10 USD，扣余额 6 USD |
| 分组 B | 是 | 留空：沿用现有倍率 | 现有适用倍率为 0.85 时，基础费用 10 USD，扣余额 8.5 USD |
| 分组 C | 否 | — | 不可选择或调用 |

建议第一期采用以下规则：

- 分组授权和报价分别判断：保留现有余额分组访问规则及管理员的授权配置，不因为新增企业身份自动扩大权限，也不因为没有企业专属倍率而撤销现有余额组资格。管理员可沿用现有分组配置调整可用范围。
- 企业倍率允许留空，表示“沿用现有倍率”；明确填写时必须为有限且大于 0 的值，可以大于 1。清除企业倍率后恢复现有计价路径，不清除普通用户专属倍率。
- “确实未设置企业倍率”与“查价失败”必须区分：前者沿用当前有效规则，后者明确报错，不把读取失败误判成没有配置。
- 现有订阅分组不直接开放为企业余额组。需要相同模型能力时，建议复用上游账号建立独立余额分组，不改变原订阅分组和其他用户的权益。
- 允许分组与企业倍率在用户设置中原子保存；身份转换是独立的确认动作，原子保存账户类型、月卡终止、折算余额及审计记录。转换不隐式保存编辑草稿。所有管理员修改入口都维持同一约束，包括分组页批量倍率、清空倍率、批量换组和修改组类型。
- 列表显示“企业”标签并支持类型筛选。保存前显示对既有密钥的影响，不自动删除密钥。

### 3.2 计价优先级

**设置企业专属倍率时，覆盖普通客户倍率；没有设置时，完整沿用该用户现有计价规则。** 企业专属倍率不与普通倍率叠乘。

```text
基础费用 = 实际用量 × 对应模型/计价项目的基础单价
设置企业专属倍率：企业扣费 = 基础费用 × 该企业用户在实际计费分组的企业倍率
未设置企业专属倍率：企业扣费 = 现有计价路径计算结果
```

例如普通分组倍率为 1.5、用户原专属倍率为 0.8、企业倍率为 0.6、基础费用为 10 USD，企业扣 6 USD。清除企业倍率后回到原用户专属倍率，扣 8 USD，而不是回到分组 1.5。原来没有用户专属倍率时，继续使用当前分组及其他已生效计价规则。

未设置企业倍率时，现有临时倍率、图片/视频独立倍率等按原有优先级处理，不额外乘一个企业系数，也不在转企业时冻结为永久旧价格。设置企业倍率时按明确的企业系数覆盖客户倍率。基础单价调整仍会影响费用；本期不实现完整合同价目表锁价。

建议明确设置的企业系数统一作用于企业开放能力中的文本、图片、视频、语音收费项目；保留各项目原有的计量单位和基础单价，覆盖图片/视频等独立的客户倍率，避免只改文本路径。未设置时这些能力保持原计价行为。上游账号成本倍率继续用于成本统计，不参与企业客户扣款。

现有部分能力有独立计价或尚未完成扣费，不能直接宣称复用一个倍率即可覆盖：

- 图片和视频可配置独立倍率，需要增加企业优先级。
- 语音、实时会话须逐条核对收费入口，已有计费路径接入同一企业规则。
- 当前 `openai_live.go` 明确记录 Live 暂不计费。建议企业第一期不开放该能力，后续单独补齐计费后再开放；不能默认为企业免费能力。

消费记录保存本次实际计费分组、实际倍率、扣款和计费时点。同步请求在准入时确定价格；异步任务创建时保存快照，结算与重试使用同一快照。后续改倍率不重算历史账单，也不改已经受理任务的费用。

### 3.3 复用数据与权限

- 复用 `user_allowed_groups` 和 `restrict_public_groups` 表达现有分组授权，设置报价本身不授予分组权限。
- 在现有 `user_group_rate_multipliers` 的 `(user_id, group_id)` 记录上增加可空的 `enterprise_rate_multiplier`；保留原 `rate_multiplier` 和 `rpm_override`。必须分别保存企业和原用户倍率，才能正确实现“未设置企业倍率沿用当前拥有的倍率”。
- 企业倍率仅在 `account_type=enterprise` 时参与计价；普通账户不因残留企业报价受影响。查询、同步和清理该表时要保留另外两类配置，不能把只含企业倍率的行误删。
- 不新增企业组织、员工、部门或第二套余额账户。第一期“企业用户”仍是现有的一名用户。
- 只返回该企业获准分组的目录、状态与倍率，不把所有公共渠道当成企业可用渠道。
- 多分组 Key 的每个候选组分别校验资格并解析企业或继承价格；无合格候选时拒绝新调用。
- 旧单组 Key、未分组 Key、模型路由、Composite、fallback、已绑定会话均不能绕过企业授权。沿用现有“实际计费分组”的归属语义；内部调度到上游账号不应误计为第二次客户分组消费，也不能偷偷转入订阅结算。
- 管理员变更后的新请求使用新规则。覆盖 API Key 鉴权缓存、各进程的用户倍率缓存、可用分组目录和计费缓存的失效；旧请求及既有任务按原快照完成。
- 持续会话在下一个可计费操作前重验资格；失去资格则拒绝继续产生新消费。已有异步任务的查询和结算继续按原资源归属完成，账户/密钥停用仍遵守已有拦截规则。

## 4. 企业余额充值

企业充值倍率独立于普通用户的 `balance_recharge_multiplier`，默认 **1**，不跟随普通充值倍率调整，不叠乘普通充值倍率或分组消费倍率。

建议在现有支付配置中新增站点级 `enterprise_balance_recharge_multiplier`，默认 1，明确设置时须为有限且大于 0 的值；不增加每个企业各自的充值配置。未配置时使用 1，不能回退到普通充值倍率。支付币种、手续费、限额、支付渠道、微信恢复、退款和金额精度复用现有流程。

```text
企业到账余额 = 充值本金 × 企业充值倍率（默认 1）
普通到账余额 = 充值本金 × 普通充值倍率
```

本金沿用现有充值请求的金额口径，手续费按原规则单独计算。即使普通充值倍率为 2，企业默认仍按 1 到账。checkout 预览、建单与支付恢复必须使用同一企业规则，客户端不能指定最终到账额、冒充普通账户或传入普通倍率。

企业购买页仅保留余额充值。订阅、月卡、优惠码等活动入口和接口继续禁止，企业充值不给邀请人新增返利。

订单保存账户类型、倍率来源、实际倍率、支付金额、到账金额和返利资格；回调、重试和退款按原单金额执行，不能按当前配置重新计价。转换前尚未支付的普通充值订单需关闭后按企业规则重新下单；已付款的先按原订单完成对账和履约，再进行身份转换，不能借保留旧付款链接让企业继续参与普通充值倍率。

下单、权益发放和账户类型切换必须进行并发校验。已关闭的普通充值订单或活动订单若出现晚到付款，仍须验签、对账并退款或转人工处理，不能吞掉成功付款、改写原单金额或直接给企业发普通倍率余额/套餐。历史已完成充值的余额保留，不追溯重算。

## 5. 普通用户与企业用户之间的转换

### 5.1 普通 → 企业：先预览折算，再确认执行

管理员在用户管理选择“企业用户”时，服务端先检查是否持有拼团月卡套餐。持有有效月卡才进入折算弹窗；没有可折算月卡时按正常身份设置流程切换，不要求填写折算倍率、不创建零金额折算单。确认保存时仍重验月卡清单，防止预览后新购月卡被遗漏。

弹窗自动列出该用户所有有效月卡及其来源订单/卡号、分组、到期时间、总额度、已用和剩余，并汇总剩余总额度。管理员只设置折算倍率和确认结果，不手填剩余额度。预览和调整倍率不写余额、不终止月卡；取消弹窗保持原样。

| 月卡 | 总额度 | 已用额度 | 剩余额度 |
| --- | --- | --- | --- |
| 月卡 A | 200 额度 USD | 100 额度 USD | 100 额度 USD |
| 月卡 B | 80 额度 USD | 30 额度 USD | 50 额度 USD |
| 合计 | — | — | 150 额度 USD |

例如管理员设置折算倍率为 0.2，转入余额为 30 USD；原余额为 12 USD 时，弹窗显示“预计转换后余额：42 USD”。确认按钮文案为“确认折算并切换企业用户”，同时明确“这些月卡将结束，后续消费使用余额”。

```text
月卡剩余总额度 = Σ max(0, 每张有效月卡总额度 - 该卡累计已用额度)
转入余额 = 月卡剩余总额度 × 管理员确认的折算倍率
转换后余额 = 执行时当前余额 + 转入余额
```

折算倍率和调用消费倍率分开：前者用于本次月卡总剩余额度转余额，后者用于后续 API 消费。弹窗明确单位，对全部月卡的剩余合计采用一个管理员确认的折算倍率，不增加逐卡定价或人工核额。剩余合计非零时，折算倍率必须填写且有限、大于 0，不自动套用企业消费倍率或充值倍率。

### 5.2 剩余额度口径

- **拼团月卡功能中的月卡**：数据来源为当前用户的 `month_card_cards`。按用户汇总全部有效月卡，跨分组、跨团逐卡求剩余后相加，不只取某一张卡、某一团或某一分组。现有月卡功能中的独购卡同样是独立月卡记录，纳入“所有月卡”的汇总；旧 `user_subscriptions` 不纳入。
- **额度**：按 `max(0, total_quota_usd - total_used_usd)` 读取；采用当前已生效额度，不预支未来拼团升档。周额度只限制使用速度，不截断整卡剩余，也不能叠加到月总剩余上。
- **已过期、退款、撤销、已折算的月卡**：不计入剩余合计，不重复折算。有效但已用完的月卡不增加余额，转换时结束使用资格；总剩余为零时明确显示零入账，不要求管理员填写无意义的折算倍率。
- **旧订阅**：不折算、不按周期额度估算、不开放人工填写；保留记录，企业期间禁止使用及续期，不自动退钱或延期。身份确认时说明已有旧订阅不属于本次折算范围。

历史余额、历史赠额、冻结余额和其他非月卡权益均不算月卡剩余，不重新折算。

### 5.3 原子执行、并发和重试

确认接口由服务端重新计算全部有效月卡的剩余合计，不能信任客户端提交的总额度、卡列表或最终余额，也不能允许客户端故意漏掉一张卡。金额使用现有 decimal/NUMERIC 口径，先求剩余合计再乘折算倍率，按余额账本精度量化，避免前端两位小数参与实际入账。逐卡入账分摊采用确定的尾差处理，确保明细之和等于总入账。

1. 校验管理员权限、操作幂等标识和预览版本，建立短暂的账户转换保护，阻止新调用准入、活动下单及新权益发放。预览阶段不冻结账户。
2. 检查未结算请求、长连接、异步任务、待付款普通充值订单、待履约活动订单和退款。存在仍会消耗待折算月卡的请求时，不完成转换，提示等待结算后重新预览；多实例都必须遵守转换保护，不能只看当前进程的在线数。
3. 在统一事务和一致锁顺序中重新读取用户余额、所有待折算权益、对应订单与报价。与准入/结算、拼团升档、退款互斥，不能只锁用户而遗漏可被其他团员操作更新的卡。已结束但尚待计费落账的请求也属于未结算。
4. 若月卡清单、额度、余额、有效期或折算倍率发生变化，返回新预览要求重新确认；不悄悄按另一个金额执行。保护失败或事务回滚后恢复原身份和正常准入，处理超时/进程退出的恢复。
5. 同一事务中记录折算单及逐项明细、终止已折算权益、增加余额、保存企业类型和审计记录；任何一步失败全部回滚。身份与余额变化只在成功提交后生效。
6. 提交后同步余额、订阅资格、Key 鉴权、企业报价及模型广场缓存。重复点击、超时重试返回同一折算结果；每份来源权益只能成功折算一次，不能重复加钱。

企业分组报价与授权在用户编辑中单独保存，转换弹窗只提交身份和月卡折算，不隐式保存尚未提交的编辑项。可以预先设置企业报价；未设置时转换后立即按原有倍率计费，符合已确认的回退规则。

已经受理的余额任务若与套餐折算无关，可按原快照继续；若会改变预览承诺的余额，应刷新预览。不能把已受理的订阅调用在转换后偷偷改成余额全额补扣。缺乏可靠的未结算识别时，转换应明确失败，不能以“行锁足够”替代这一检查。

### 5.4 权益终止与账务记录

- 保存独立的企业转换操作及月卡明细，关联用户、管理员、来源卡/订单、额度快照、剩余合计、统一折算倍率、入账金额、前后余额、时间和幂等标识。通过数据库唯一约束保证每张来源月卡只折算一次。
- 月卡增加可识别的“已折算”终态，历史记录保留，后续消费、续期、重置、拼团升档、退款重试和后台补发都不能使其重新可用。旧订阅不写入“已折算”状态。
- 原支付订单保留真实支付状态，折算不是原路退款。现有 `RevokeOrder` 要求订单已经退款，不能伪造 `REFUNDED` 调它完成转换。
- 已折算团员保留历史参团记录和已形成的团人数，不再获得后续升档额度；不降低其他成员已得额度、不重新招募。所有升档 SQL 都要排除已折算卡，不能继续只判断 `status<>'revoked'`。
- 入账归类为“套餐转余额”，复用余额历史展示，但不作为新现金充值、不触发充值倍率、不累计为新的实付充值、不产生邀请返利。不能直接调用会触发管理员充值返利的现有业务入口。
- 已折算订单后续退款必须关联原折算记录和已转入余额处理，禁止直接套用原全额退款逻辑重复返还；需要冲回时在现有管理员退款流程中明确展示。欠费或余额已花掉时不能静默抹平差额。
- 未支付的活动订单和普通充值订单需要先关闭或完成对账；切换后新充值使用企业倍率。关闭订单的晚到付款走退款/人工处理，不生成企业套餐或普通倍率充值余额。

### 企业 → 普通

同样只允许管理员操作。保留原有普通专属倍率、分组授权和余额；企业倍率停止生效，可保留配置备查。授权和普通倍率在用户编辑中单独保存，不自动扩大分组访问范围。已折算套餐永久保持终止，不因转回普通而恢复，也不允许第二次折算；以后正常购买的新套餐单独计算。

历史企业订单、未完成任务继续使用建立时的价格和返利资格，不能因转为普通而补发活动赠额。

## 6. 企业报价、提醒和月度对账

### 6.1 模型广场

企业用户每次打开现有模型广场，默认选中“仅看企业用户倍率”；普通用户和匿名用户不显示该按钮。重新进入页面恢复选中，不用上次取消选择的浏览器偏好覆盖该默认。

- **选中**：在当前可见分组范围内，只展示为该企业用户明确设置了 `enterprise_rate_multiplier` 的分组及其模型，使用该企业专属倍率显示报价。未设置企业倍率的分组全部隐藏，不用普通倍率补位；是否配置以字段是否存在判断，不比较数值是否与普通倍率相同。
- **未选中**：恢复现有普通用户的分组可见范围与普通倍率展示路径（包含原有用户专属倍率逻辑），不把企业倍率继续混入普通报价视图。
- **没有企业报价**：默认选中时显示“暂无已配置的企业倍率分组”，可取消选择查看普通报价；不能自动取消或展示继承倍率。
- **实际调用**：此按钮只改变报价展示。没有企业专属倍率的组即使在选中状态被隐藏，只要原有授权允许，仍按现有倍率调用；取消选择也不会让已设置企业倍率的组改按普通倍率扣费，更不会切回普通账户或恢复活动资格。

后端分别提供本人企业专属倍率和普通视图使用的倍率/来源；企业报价视图与企业实际计价一致，普通报价视图明确属于普通价格查看。前端不能用一个通用系数估算所有图片/视频/语音价格，切换后筛选项、模型列表和报价一并更新。加载失败显示获取失败，不把错误当成未配置或伪装成普通价格。只返回本人报价，不能向浏览器暴露其他企业的专属价格。

### 6.2 低余额提醒

复用现有余额通知开关、阈值、附加邮箱和邮件发送机制，在个人资料中配置，不新增一套企业通知服务。套餐转余额只是余额账变，不作为新实付充值放大按充值额计算的阈值基数；及时刷新通知读取的余额。

### 6.3 月度对账导出

在使用记录增加月份选择和“导出月度对账”入口，复用现有 CSV 下载能力及筛选习惯，支持按分组、API Key 核对。

- 默认当前月，按站点配置时区确定自然月的 `[月初, 下月初)` 范围；文件写明月份、时区、统计截止时刻和 USD 单位，当前月标为截至导出时的账单。
- 默认提供完整月度 ZIP 对账包，含汇总、明细和折算流水三份 CSV，三份在同一只读 Repeatable Read 事务中读取；也可分别下载单份 CSV，单独下载彼此不承诺同一快照。汇总按“实际计费分组 × API Key”统计请求数、用量、基础费用和实际消费；明细包含请求/记录标识、时间、分组、Key 名称与 ID、模型、计量项目、实际倍率和实际消费，不导出 Key 密文。
- 按账单记录的实际倍率和费用汇总，不能用今天的企业倍率重算整月。月中转换用户的历史个人消费也保留，区分余额消费和订阅额度消耗，不能把订阅消费全算作现金余额支出。
- 套餐转余额作为单独的余额入账项列出，包含折算操作号和来源权益摘要，不抵减 API 消费、不冒充充值。第一期导出范围是月度消费对账及本功能的折算入账，不宣称是涵盖所有历史收支的完整财务总账或发票。
- 服务端对整月全量数据做汇总；明细导出固定统计边界和数据快照，完整取数，不能只导当前页，不能随着新日志写入漏行或重复。大数据量采用现有分页/流式基础设施，超限明确提示，不能静默截断。
- 导出与页面筛选使用一致口径，只能读本人数据；汇总总额等于同次导出明细的金额之和。CSV 做必要转义和公式注入防护。

## 7. 接口和实现落点

接口沿用现有响应包装；以下新增字段和错误码是拟定契约，开发前统一到项目风格。

| 位置 | 拟定变化 |
| --- | --- |
| 登录、会话刷新、`GET /api/v1/user/profile` | 用户数据增加 `account_type` |
| 管理员用户列表、详情、创建和更新 | 支持 `account_type`；复用 `allowed_groups`、`group_rates`；增加可空的 `enterprise_group_rates` 和类型筛选；已有账户转换必须走确认流程 |
| 管理员转换预览 | 检查是否有拼团月卡套餐，自动读取全部有效月卡的剩余合计及明细，返回统一折算倍率、入账额、前后余额、冲突项和预览版本；不修改数据；无可折算月卡时不进入折算流程 |
| 管理员确认转换 | 接收预览版本、幂等标识、分组/企业报价和统一折算倍率，服务端重查全量月卡后原子完成月卡终止、余额入账和身份切换；不接受人工额度；过期预览返回 409 |
| 用户资料更新 | 不接受用户修改 `account_type`、分组或倍率 |
| `/groups/available`、`/groups/rates`、渠道/监控 | 沿用授权判断，返回明确的企业报价或继承来源，未设置不判为缺价 |
| `/model-plaza` | 企业响应分别提供本人企业专属值、普通视图报价及来源；默认选中仅看企业倍率并隐藏未配置组，取消后切换到普通分组倍率查看 |
| 用量月度汇总/导出 | 复用用量查询条件，服务端计算整月汇总及一致快照明细，附带本月套餐折算入账 |
| 管理员支付配置 | 企业充值倍率独立字段 `enterprise_balance_recharge_multiplier`，默认 1，与普通充值倍率分别展示和保存 |
| `/payment/config`、`/payment/checkout-info` | 企业仅有余额充值选项，返回企业有效充值倍率（默认 1），不读取普通充值倍率作为企业值 |
| `/payment/orders` | 企业仅允许余额订单，使用企业充值倍率，拒绝订阅/月卡和优惠码；类型和倍率来源由服务端决定 |
| 拼团、订阅购买/领取、兑换、邀请返利 | 企业受限操作返回 403 和稳定错误码，例如 `ENTERPRISE_FEATURE_FORBIDDEN` |
| 查价失败、转换冲突 | 查询失败与未配置企业报价分开；冲突返回 409 并附重新预览/处理原因 |

实施范围按现有结构集中处理：

- **用户与存储**：`backend/ent/schema/user.go`、增量 SQL 迁移、生成代码、用户 repository/service/DTO；旧用户默认个人类型。用户分组表增加独立企业报价，新增转换操作/明细及已折算权益状态。
- **管理员**：`admin_user.go`、`admin/user_handler.go`、用户分组配置、分组批量倍率与改组类型入口；复用事务和审计。
- **身份与授权**：JWT 当前用户上下文、API Key 鉴权快照、单组/多组选组和资源归属。几个清晰的企业校验函数即可，不搭通用权限平台。
- **费用与快照**：`user_group_rate_resolver.go`、通用与 OpenAI 用量计费、图片/视频/语音、异步任务快照；区分企业报价、继承及读取失败，准入、费用展示、扣款及已有利润保护使用一致口径。
- **折算与账务**：全量有效月卡剩余自动求和、统一折算倍率、短暂转换保护、未结算检查、用户/卡/订单锁顺序、余额原子增加、审计及幂等；不查询旧订阅作为可折算额度、不增加人工核额接口。
- **支付与活动**：支付配置增加独立企业倍率，`payment_order.go`、checkout、恢复/履约/退款按账户类型选择倍率并保存快照；复用金额计算函数。monthcard、subscription、redeem、promo、affiliate、默认订阅和返利后台任务继续执行企业限制，月卡查询/升档/退款适配已折算终态。
- **报价与对账**：`model_plaza_handler.go`、广场 DTO 的企业/普通价格、默认选中与缺企业配置过滤、usage repository 的月度汇总和一致快照导出、折算入账查询。
- **前端业务逻辑**：用户类型、auth store、导航与路由守卫、禁止的接口请求、充值与密钥接口对接；由主代理负责。
- **前端视觉交互**：企业工作台、六页企业展示、模型广场按钮、月度导出交互、后台企业配置与折算确认弹窗；由 Kimi K3 负责。

代码核对时发现两处直接影响本需求的现状，实施时必须一起处理：

1. `admin_user.go` 目前先更新用户，再同步分组倍率；倍率失败只记日志。企业报价和用户编辑字段保存需要真正的事务和失败返回；身份转换与用户设置为两个明确操作，转换未配专属报价时按已确认的普通倍率回退规则计费。
2. `user_group_rate_resolver.go` 目前查价失败会回退分组默认价格，且有进程内缓存。企业必须明确区分“未配置，按用户要求继承”和“读取失败”，并解决跨实例更新。`model_plaza_handler.go` 也有报价读取失败后回退的展示逻辑，需要一并处理。

另需注意：现有 `UpdateUserBalance` 会尝试管理员充值返利，月卡 `RevokeOrder` 要求原订单已退款，拼团升档只排除 revoked 状态；它们不能直接替代企业折算操作。现有 CSV 为浏览器逐页获取用量，不足以直接承诺并发写入下的整月一致对账。

## 8. 给 Kimi K3 的 UI 任务范围

执行参数按用户要求固定为 `kimi-k3` + YOLO；如果届时执行环境无法提供该模型，明确反馈，不擅自替换模型。主代理先给出稳定的字段、样例响应和前端业务接口，再委派 UI。

视觉建议：沿用站点品牌和基础组件，采用紧凑、清晰的企业控制台布局，优先显示余额、消费、渠道状态和密钥操作；减少活动卡片和装饰，支持移动端、键盘操作、深浅色和现有国际化。

交付内容：

1. 六入口导航、企业身份标识及默认使用记录页面。
2. API Key 分组选项清晰展示该企业的适用倍率及“企业专属/沿用现有”来源，无法使用的历史绑定有解释。
3. 渠道状态提供模型广场入口；广场对企业默认选中“仅看企业用户倍率”，只显示已设置专属倍率的组；取消选择恢复普通组倍率视图，覆盖无企业报价的空状态。
4. 充值页只有余额充值，显示企业有效充值倍率（默认 1）、支付币种、本金、手续费和到账 USD；后台支付配置显示独立企业充值倍率；充值历史作为同页页签或子入口。
5. 后台用户类型、可空企业消费倍率表单；仅有拼团月卡套餐时展示自动汇总月卡剩余总额度、统一折算倍率、转入金额、前后余额和月卡终止说明的弹窗，不提供人工额度输入；包含预览失效/处理中/完成/失败状态。
6. 使用记录的月份选择、汇总/明细导出入口、折算入账展示与个人资料中的既有低余额提醒。

UI 任务只修改约定的视图和展示组件。权限判断、路由守卫、金额公式、数据模型、支付处理和测试由主代理接入并审查；分工按文件明确，避免并行修改相同文件。YOLO 仅用于本地开发执行，不代表部署授权。

## 9. 实施顺序与验收

1. 按已确认规则补齐接口契约和企业校验入口，区分企业消费倍率、企业充值倍率与月卡折算倍率。
2. 实现账户类型、企业消费倍率/继承、仅月卡的全量剩余额度预览与确认事务、鉴权/缓存同步；准备可用的企业测试账户。
3. 接入独立企业充值倍率（默认 1）、各计费路径、活动限制、模型广场两种报价视图及月度对账，复用现有支付基础设施和低余额提醒，验证旧密钥及旧订单。
4. 接口稳定后由 Kimi K3 执行 UI；主代理完成前端业务接线和后端验证，可并行处理互不冲突的文件。
5. 集成页面和回归普通用户；独立审查通过后再按项目现有发布流程处理，方案阶段不涉及发布。

必须覆盖的验收场景：

- 企业最多保留六个一级入口，支付关闭隐藏充值、工单未开启隐藏工单，可以访问模型广场报价页；登录重定向、直输受限 URL、旧缓存、付款返回和工单子页面均行为正确。
- 用户篡改资料请求无法改身份；直接请求月卡/订阅/兑换/优惠码/返利失败，后台奖励任务也不新增企业活动权益。
- 同组不同企业按各自倍率扣费；未设置企业倍率时，原用户专属、分组及各能力现有倍率完全保持；清除企业倍率恢复原规则；明确企业价格覆盖普通系数，所有实际开放的收费能力都符合报价。
- 未设置企业倍率不阻止原有余额组使用；查价失败不冒充缺配置；组停用/删除、组改为订阅、撤销授权均不能绕过资格或进入订阅扣费。
- 多组 Key、旧单组 Key、管理员代配置、fallback、Composite、持续会话不会绕过资格；资源查询与历史结算不误伤。
- 用户、企业倍率、权益终止、余额入账和折算记录保存中途失败全部回滚；并发更新、下单、切换身份和跨实例缓存传播得到一致结果。
- 改价前受理的同步请求/异步任务按旧快照结算，新调用按新价，重试不重复扣款。
- 企业充值默认倍率为 1，修改普通充值倍率不影响企业；只有企业配置能改变企业充值倍率；前端预览、建单、支付恢复和实际到账一致；不同币种、手续费、精度、重复回调和退款均按原订单快照处理。
- 企业充值不给邀请人返利；企业邀请人不从后续普通用户充值获得返利；重试不补发。
- 仅有拼团月卡套餐时进入折算；自动汇总该用户跨团、跨分组的全部有效月卡剩余，不受列表分页或周限额截断；旧订阅、过期、退款、已折算权益不入账。无月卡不出现人工额度/折算流程，零剩余不增加余额；取消预览无副作用，重复确认不重复加钱。
- 原月卡清单与后续保存不一致时要求重新预览；客户端伪造合计、遗漏月卡或跨用户卡号无效；统一倍率作用于剩余合计，逐卡账务分摊与总入账精确相等。
- 预览后消费、到期、拼团升档或余额变化必须重新确认；未结算调用不能和折算重复消耗同一额度；失败保护能恢复，其他团员不被长期锁住。
- 折算后所有已转换套餐停止消费、续期、升档和恢复；转回普通再转企业不重复折算；退款不能与折算重复返还；折算不触发充值倍率或邀请返利。
- 转换前待付款的普通充值订单关闭，已付款订单先完成对账；切换后旧链接及支付恢复不能继续提供普通充值倍率；关闭订单异常晚到付款可追溯并能退款/人工处理，不丢钱、不发活动权益。
- 企业每次打开广场默认选中专用按钮，只显示本人明确设置企业倍率的分组；未设置组隐藏，全部未配置时显示空状态；明确设置为与普通倍率相同的值仍显示。普通和匿名用户不显示按钮，不泄露其他企业报价。
- 取消广场选择后恢复普通分组及普通倍率查看，不继续混入企业倍率；再选中恢复过滤。切换不影响身份或真实计价：未设置企业倍率仍沿用现有消费规则，已设置的始终按企业倍率收费。
- 月度导出包含完整数据，时区/月边界正确，并发写入不漏行、不重复；历史倍率不重算，月中转换前的订阅消费与余额支出分开；汇总与明细一致，折算入账可追溯，跨用户导出被拒绝。
- 低余额提醒继续使用原配置，折算不增加实付充值统计，通知读取到更新后的余额。
- 普通用户原有拼团、订阅、充值倍率、邀请码、图像/语音定价与菜单回归通过。
- 旧数据库增量迁移后现有用户仍为个人用户；一旦创建企业账户，退回不识别企业限制的旧程序会绕过新规则，发布回滚方案必须覆盖这一点。

按现有 Go 测试、数据库事务/并发集成测试及前端 Vitest/类型检查验证关键行为，补充浏览器验收；不把当前工作区其他未完成改动的状态算成企业功能的测试结果。

## 10. 最新决策记录与剩余建议

| 事项 | 当前方案 |
| --- | --- |
| 企业身份和六个入口 | 用户确认，保留；模型广场作为报价页面开放 |
| 活动限制 | 用户确认；企业不参与普通用户充值倍率 |
| 未设置企业专属倍率 | 沿用该用户现有倍率，不拒绝调用 |
| 企业充值 | 独立倍率，默认 1；支付渠道与流程复用现有能力 |
| 个人转企业 | 仅有拼团月卡套餐时进入折算，自动汇总全部有效月卡剩余，总额度乘管理员确认的折算倍率；不折算旧订阅 |
| 企业报价可见 | 每次打开广场默认选中，仅显示本人设置企业倍率的组；取消后恢复普通分组倍率查看 |
| 低余额提醒 | 复用现有能力 |
| 月度对账导出 | 本期包含，不再作为可选后续项 |

本轮已替换第二轮中“企业充值继承普通到账倍率”“旧订阅人工核定折算”“企业报价视图展示未配置组的继承价格”三项规则，不保留并行口径。

剩余实现建议：企业消费倍率显式设置时覆盖各开放收费能力的客户系数；企业充值倍率作为独立站点配置默认 1；折算倍率独立于充值和消费倍率；模型广场通过渠道状态进入以保留六项一级导航。这些细化建议与已确认需求分开记录。

“复制另一企业的分组报价”仍可留作后续后台效率改进。本期不扩展企业组织/员工权限、共享钱包、授信后付费、自动开票、合同管理、自动续费或完整合同锁价。
