# custom.7 发布检查修复

`v0.2.7-custom.7` 的 Release 成功，但同一提交的 CI 失败。发布任务原来只依赖版本文件与前端构建，不要求完整 CI 成功。

## 失败原因与修复

- GitHub 单元测试实际失败于迁移锁的取消用例：5ms 定时器可能在首条模拟查询执行前到期，留下未消费的查询期望。改用 `testing/synctest`，等待查询返回未获锁并进入重试等待后再取消，保留查询执行和 `context.Canceled` 断言。生产迁移锁逻辑未改。
- 本地完整单测另发现同线程 WebSocket 抢占用例偶发失败：在飞完成帧可以先于异步抢占关闭帧到达。测试现在允许这两种顺序，仍必须收到正确的关闭码与原因，且服务端恰好一条连接被抢占。新增 gate 固定“完成在前”的顺序，原测试在该场景稳定失败，修复后通过。生产抢占逻辑未改。
- 消费榜查询显式处理 `Rows.Close` 错误，同时保留主错误；缓存返回值检查类型与 nil。消费榜及侧栏测试补全类型断言检查，后端全量 lint 为 0 问题。

## 发布门槛

CI 可作为 reusable workflow 接收固定源码 SHA；汇总任务要求 shell、后端测试、前端检查和 lint 全部成功，失败、跳过、取消均不会放行。

自动和手动 Release 先解析版本标签，再让 CI、版本文件、前端和发布构建都使用同一个 SHA。发布任务显式依赖 CI，发布前重新核对远端 tag 未移动或删除；只有发布任务拥有仓库与镜像写权限。标签推送不再重复启动单独的 CI，而由 Release 调用完整 CI。消费榜 PostgreSQL 测试也接入 CI 的隔离数据库。

本地工作流回归执行真实 Git 引用和工作流脚本，覆盖 13 组 CI 结果、非法标签、手动发布分支不同于标签、轻量 / 附注标签和标签移动 / 删除；actionlint 通过。手动重发本补丁前的旧标签可能因缺少新的工作流回归文件而被拒绝，应以新的补丁标签发布。

- WebSocket 同线程两种时序及不同线程场景共 600 次通过，相关 race 测试通过。
